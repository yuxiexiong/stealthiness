# 文件存放与上传规则

适用本次 2026-10-12 归档补齐；不追溯删除或改写既有历史。

- GitHub 收源码、配置、实验合同、人工结果报告、必要的小型机器结果 / 成本收据，以及自制的小型研究指南。
- 本次新上传单文件不得超过 **2 MiB（2,097,152 bytes）**。按文件清单逐项选择，不使用 `git add .` 将工作区全量提交。
- 模型与检查点（`.safetensors`、`.pt`、`.pth`、`.ckpt` 等）、虚拟环境、数据缓存、训练数据、私有逐题回答 / logits / witness、大型报告与图集、论文全文 PDF、部署压缩包不补传。
- 大产物清单记录原路径、字节数、时间、用途、已知哈希来源及备份状态。没有实际计算哈希或验证独立备份时写“未核验”，不以服务器文件存在代替备份证明。
- 本地与 H20 同名但不同内容的源码保留来源快照与哈希，不默默覆盖当前版本。冻结依赖若独立运行需要，允许保留必要的小副本并在清单解释。
- 原有大文件、旧草稿、失败实验、历史分支与服务器目录均保留。本次不清理 Git 历史，不删除文件，不启动 GPU 工作。

首页指向当前结果与源文件；完整历史产物可通过原分支或清单定位。未来正式迁移大产物需先核验可读取的备份和校验值，再单独决定是否清理旧副本。

提交前运行 `python3 research/repository-reconciliation-2026-10-12/check_upload.py`，检查暂存文件的大小和资产类型；提交后可传两个 Git revision 检查本次差异。它不扫描或删除历史大文件。
