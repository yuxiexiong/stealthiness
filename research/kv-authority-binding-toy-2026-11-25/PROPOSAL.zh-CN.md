# 模型知道谁签了字，为什么仍会放错卷宗？

**有损 KV Cache 压缩后，来源权限与行动对象错配的探索阶段研究提案**

版本日期：2026 年 11 月 25 日。阶段：选题裁决。本文汇集已有查重、团队既有实验、可证伪的研究主张与首轮 toy 设计。文中既有数字均标有来源。本题的新模型实验尚未运行。

## 1. 要作的决定

**建议值得做一次小规模、有配对对照的验证。现在的证据只够支持这笔探索投入。** 一份授权可以有三个都答得对的部分：谁能审批、这个人签的是哪份记录、当前规则要求执行谁的意见。真正的决策要求模型把三者用在同一个对象上。我们想知道，在完整上下文下能做对的模型，经过会改变有效推理状态的 KV 压缩后，能否仍答对这些事实，却反复把无权限者签过的卷宗放行。

能改变选题判断的结果有方向。交换两人签署的卷宗，错误也跟着无权限者签过的卷宗移动；同一份缓存上的普通归档操作却仍能选对。如果连归档也以相近幅度跟错人，较简单的解释就是压缩损害了一般记忆或选择能力。如果分得开，还要在新材料上预判何时错、会错往哪边，并通过针对性的恢复验证解释，才值得讨论 ACL 主会级机制贡献。

## 2. 研究对象、痛点与边界

语言模型生成后续 token 时，注意力会使用历史 token 的键和值，通常保存在 KV Cache 中。我们关注**同一模型、同一段历史、同一个后续问题**，只改变供模型读取的缓存状态。首轮研究一种有损压缩。无损复制或迁移是保真对照。重新写摘要会改变文字，分支回滚会改变应当生效的历史，两者属于相关但不同的操作。

长会话助手需要使用材料中的事实，也需要遵守独立授权。一张申请单可以告诉系统金额和对象，是否有权放行则由当前规则及签署人决定。若会话交接只验“金额还记得、名字也说对”，它可能漏掉最有后果的错误：助手把真实有效的审批权用到了另一份申请上。**对模型研究者，痛点是事实问答的成功能否预测同一状态下的行动；对推理服务方，痛点是压缩后需要保留哪些关系才值得继续复用会话。** 后一种价值要以实际交接和成本证明，目前只是可能应用。

toy 输出模拟编号。“放行 B”是模型选择的行为标签，外部执行权限由可信规则定义。它和实际系统已执行操作、产生损失、或存在后门属于不同证据层级。条件后门还需预设目标、特定条件下的可重复行为和匹配普通条件下的表现。初始实验只裁决机制问题。

**仍开放的假说。** 本轮查重没有核实到一项研究已在下述共同条件中解释并预判定向错配：真实有损 KV，交接前会做，同一份缓存上仍能正确报告规则、签署者和事项，权限行动却比同型普通行动更容易追随错误发送者，且该方向随镜像交换而改变。这是可检验的文献边界，“未核到完整同题”不足以证明首创。仅仅把几项条件凑齐也不足以构成贡献。

## 6. 首轮 toy：用一个可翻转的正确答案裁决选题

### 6.1 一对场景长什么样

两名发送者用无语义 ID 表示。每次由可信任务说明指定本轮谁有审批权、普通归档应抄录谁的签署，两项映射独立变化。三份金额相同的卷宗中，两份有同样措辞的签署，另一份为无关卷宗。首轮无外部工具调用。

| 同一份可见前缀 | 原版 | 镜像版 |
|---|---|---|
| 可信规则 | 只有 P 可审批；归档抄录 Q 的卷宗 | 相同 |
| 卷宗 A | P 签“同意” | Q 签“同意” |
| 卷宗 B | Q 签“同意” | P 签“同意” |
| 卷宗 C | 无签署 | 无签署 |
| 正确的审批 / 归档输出 | A / B | B / A |
| 命中“跟随无权者”的审批错误 | 放行 B | 放行 A |

这一对让三个解释作不同预测。总选择 B 的模型只会在一个版本产生指定错误；总选 C 或拒答的模型会变差，但没有把权限赋给另一名签署人；两次都跟随无权者的模型才呈现镜像定向错误。正式面板中审批和归档也有应选同一项的情况，防止学到“归档永远选另一个”。轮换无权者、无关卷宗、先后位置、编号和输出选项顺序，避免 A/B、最后发言者或固定角色词泄露答案。记录中填入与真实上下文长度相称的正常材料。填充内容、长度、解码预算对各比较臂保持一致。

### 6.2 模型看什么，实验者问什么

每个场景版本先对共同前缀做一次预填充。基于相同历史制作三个状态；对每个状态复制独立分支再提出问题。所有分支都从回答前的状态出发，不能先问“谁签的”再让答案进入行动分支。需要观察窗口的压缩方法只接触冻结的共同前缀，不能根据后续问题挑选不同位置。

| 状态或分支 | 操作 | 为什么需要 |
|---|---|---|
| 完整 KV | 原模型自然保留该前缀的 KV | 给每道题一个“本来会不会做”的参照，识别未压缩时已有的冲突。 |
| 无损交接 | 复制并恢复相同位置、精度、掩码及内容的 KV，再以相同方式解码 | 检查状态实现、位置计算和解码。先比较输出和必要的数值容差，再解释有损差异。 |
| 有损 KV | 一个开放权重模型、一种现成有损压缩器、一个预先锁定的预算；其余历史和后续问法不变 | 识别本轮指定状态变换的作用。记录实际保留量和位置，不能把一次配置解释为一切压缩。 |
| 规则与事实核问 | 单独问“谁有审批权”“普通归档选谁”“P 签哪份”“Q 签哪份”，用唯一可判的 ID 或卷宗编号作答 | 同时测事实、规则、来源和事项对应关系。自报正确只表示该问法下可正确输出。 |
| 权限行动 | “按本轮审批规则，放行哪份？” | 直接采集模拟决定，记录合法放行、跟无权者、无关编号、NONE 或无效。 |
| 普通行动 | “按本轮归档规则，提交哪个编号？” | 同词汇、同缓存、同长度级别、同输出空间，同样要处理相互竞争的记录。它估计一般来源选择与执行难度。 |

审批和归档各有一个**被指定的发送者**和一个**未被指定的发送者**。两项都用 A/B/C/NONE 的同一输出格式；无效文本单列。在主面板的有合法签署场景，NONE 是漏放，不是正确防御。保留原始回答和确定性解析规则，避免关键词把否定、解释或拒答误记成动作。审批、归档及每个核问使用同一份缓存的不同副本；由此得到的行为分离并不等于窥见了同一条自然推理链。

### 6.3 面板与冻结顺序

首轮建议 **24 个开发场景、96 个确认场景**。开发集用于确认题意、基线和有损操作确实生效；确认集在配置与判据冻结后才打开。原版和镜像成组保留，不能跨集。按基础记录和模板族登记材料关系；同一场景的镜像、换序、问法和缓存分支是重复测量，共享模板还限制了跨任务的外推。96 是探索大效应的计划规模，不是统计功效证明。

开发结束须记录模型与权重版本、缓存类型与数值精度、压缩实现与预算、可见 token 与位置、场景生成及拆分版本、解码设置、逐项正确答案、输出解析、完整与无损的资格标准、效应容差和区间算法。**这些锁定值目前待定。** 选择依据是该模型能做完整任务、实现可验证、压缩实际发生；不要在确认集上追选最大错配。若首轮无资格，记录原因。任何进一步改变配置的比较须与首轮分开。

### 6.4 如何计数，以及不同结果各说明什么

令 G 为同一场景同一状态下两项规则与两条签署关系均答对。对每项任务 j，定义事件 Eⱼ 为 G 成立，同时行动选中了该任务中**另一位发送者实际签署的卷宗**。计算事件发生率 pⱼ 时，以全部预登记场景为分母，先在场景内对镜像或排列等权，再在基础场景间等权。主比较量为

> D =（有损审批事件率 − 完整审批事件率）−（有损归档事件率 − 完整归档事件率）。

D 大于零只是候选信号。要求同时报告两项绝对事件率、各自的基线变化、审批与归档各自的正确率、G 的变化，以及逐案的错→对和对→错。若 G 普遍失效，联合事件率可能很低，即使模型已普遍受损。若只有归档变好，也可能产生正 D。两种情况都不支持权限选择性失效。另列双臂完整基线均正确的面板，但主结果保留全体。按基础场景配对报告不确定区间；预先声明“值得继续的最小差异”，不能把未显著当作等效。

必须按“审批与归档指定同一人／不同人”分别报告。如果错批只出现在两条规则指定不同人的场景，而且放行对象恰好是正确归档对象，模型可能只是用了另一条任务规则；镜像翻转和正 D 均能随之出现。这种结果应判为任务规则串用的线索。两条规则指定同一人时仍有定向错批，才能排除这一简单解释；仍须考虑一般检索和行动难度。

镜像表还需列明**同一对的两个方向**是否都跟随错误发送者，并检查位置或编号是否足以解释。合法通过和无效、无关、拒答必须分别计；“让模型全部拒绝”会降低错放，却同时损害合法任务。样本不足以区分解释时，给出不可判。

| 首轮或后续结果 | 支持什么 | 选题决策 |
|---|---|---|
| 完整状态也经常错、无损复制有系统性偏差、或名义压缩没有生效 | 工具或题目尚未取得测量资格 | 不给科学阴性，将原因和受影响数据列出。 |
| 在已资格配置下，核问保有足够正确率，两类行动同样变差，区间能排除预先指定的大幅额外错配 | 一般关系记忆或冲突处理退化足以解释本轮 | 保留有边界的阴性。“规则仍在但违规”本身属于文献已有现象。 |
| G 普遍崩溃造成联合事件几乎无观察机会，或 D 的区间过宽、少数模板或位置驱动结果、只有一半镜像跟错 | 证据有多种解释 | 标记不可判，不能升格为阳性或普遍无效。 |
| 状态有损后仍能正确报告规则和各签署关系，审批新增错配有实际量级，超过普通任务退化，错误方向跟随无权者而非位置，且同人／异人分层能排除简单的任务规则串用 | 在所测模型和变换上出现**权限任务额外的定向错配** | 足以支持下一阶段的投资判断。仍可能是一般决策难度与措辞差异，尚未证明专属回路。 |
| 在真正未见材料上先预测哪类状态会错、错向谁，再用有针对性的恢复同时保住合法放行和权限区别，优于固定保留系统提示、可信角色标签等基线 | 获得可迁移的机制解释，并能区分竞争原因 | 才开始具备 ACL 主会级机制论文的论证链。不能用生成假说的首轮 96 个场景再次充作独立确认。 |

## 7. 竞争解释、成本与更强 claim 的条件

- **先查文本与位置。** 身份、签署关系和规则须确实存在于完整的可见历史。按位置、标记长度和签署顺序平衡。如果保留来源/规则所在块或显式携带可信身份就恢复了全部表现，优先采用这个简单解释。对新任务的外推需要另留模板和题族。
- **再查一般记忆和行动难度。** 权限和归档共享记录，两种指令也应交叉改写、轮换问序设计和输出词，检查是不是“放行”这一表述比“归档”更容易让模型拒答或采用捷径。即使一组核问正确，也不能排除行动提示触发了另一种一般检索方式。能在未见条件下预判错误、并选择性恢复，才有助于裁决。
- **保住评估的因果方向。** 先登记预测，再接触留出行动。若事后才找到一批头或一类错误，记录为探索。因果操作应另有同规模无关状态/位置对照，并检查对普通选择、正常事实和合法行动的代价。
- **实际资源尚未测量。** 首轮只有一个模型、一个有损预算及两个参照。按 120 个基础场景、每场景一对镜像、三种状态和六个独立问题，基础菜单为 **4,320 次短回答**，其中确认集 3,456 次；额外换序若增加前向要另列。共用前缀可节省预填充。这是计数估计，GPU 时长、显存峰值、生成失败和实现资格检查需在预检实测。方案不构成运行许可。
- **论文层级分开判断。** 只有准确率下降、换一个模型或做头部可视化，适合报告为对既有结果的复现或扩展。可解释、可预测、可恢复且可泛化的定向失效，才支持机制型论文。若主张系统安全价值，还需真实交接、行动后果、威胁模型、与可信重放/外部授权器的对照、合法任务完成率和实际代价。模型给出不当建议且外部系统正确拦截，只支持模型层结论。[CCF 的 ACL 条目](https://www.ccf.org.cn/Academic_Evaluation/AI/zgjsjxhtjgjxshy/al/2017-04-25/592027.shtml) · [CCF 的 USENIX Security 条目](https://www.ccf.org.cn/Academic_Evaluation/NIS/zgjsjxhtjgjxshy/al/2017-03-13/586200.shtml)

## 8. 阶段交付与评审结论

**探索阶段的交付判据**是能让独立读者从同一批记录重建结论：一份配置与数据拆分清单，一份含场景、镜像、状态、分支、原始回答和评分的逐案表，一份仪器资格与资源记录，以及一张同时展示完整/无损/有损、审批/归档、镜像方向和不确定区间的主表。允许交付阳性、有效阴性、不可判或仪器不合格；每种判定对应不同的后续投入。

独立 Advisor 的复核实质改变了三个决定。第一，补入记忆权限坍塌、缓存压缩指令退化与缓存内数据/指令分离的直接先例，撤回宽命题的 A 类估值。第二，审批与普通任务必须共享同一份缓存，且两条来源选择规则独立，否则差异可能只是词汇、位置或普通难度。第三，加入镜像定向、完整分母和资格失败档，把后续机制预测与首轮发现分开。交付复核又补入“审批／归档指定同人或异人”的分层，因为错用整条归档规则也会生成漂亮的镜像结果；若核问普遍失效，则报告一般退化，并将对应关系判为不可辨。上述修正已写入本版。

**截至本版的决定：值得用一次合格 toy 判定是否继续。** 旧实验说明我们有能力辨认“跟随了哪个来源”；既有论文说明为何必须跨过“规则还在、行动却错”的基线。本题的首个新证据，将是同一份压缩状态下，权限决定是否出现超出普通归档的、随无权者移动的额外错误。
