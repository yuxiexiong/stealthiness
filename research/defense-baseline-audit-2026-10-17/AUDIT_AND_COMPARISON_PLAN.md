## 1. 先说结论

**有必要比较机制完全不同、但能解决同一防御任务的强方法。** 审稿人关心的是：面对同一种攻击，最后能否得到安全、正常能力保得住、成本可接受的模型。不能因为对方不使用“宵禁时机”就排除它，也不能只挑与我们机制接近、恰好表现差的对手。

**目前没有找到这9项外部名称所对应的官方实现被直接运行，或带可核验上游版本的官方源码被原样运行的证据。** 实际执行路径是本地重实现、任务适配或实质不同的概念对照。不能据此说结果虚假；但不能把这些结果写成“官方方法已完整复现并败北”。

最严重的更正有四项：

1. **GraCeFul 的阶段、算法和成本归属错了。** 原法是训练前梯度过滤，然后训练一次。我们测的是污染训练结束后的梯度聚类，再重训；还换了压缩、聚类和删除规则。约1,160秒、端到端2.2倍只属于本地端点改造版，不能算到官方GraCeFul名下。
2. **GradSentry 只有本地离线检测普查，没有过滤后训练的防御结果。** 不能列成“官方GradSentry训练后失败”。
3. **“7类都做了正向对照”没有对应证据。** 已找到的是ABL本地前置投毒隔离精度0.72；其他公式测试、合成数据测试，不等于原任务或原实现的效果复现。
4. **固定预热LT已经是必须保留的强对手。** 它的适配身份需要写清，但现有打平结果仍然成立。不能通过回退到未经测试的官方默认配置，把它从主比较中抹掉。

### LT：“原版”和我们跑的版本到底是什么

LT的核心是先训练一段时间，再按近期loss分位数屏蔽高loss样本；它本来就有预热、丢弃比例和统计窗口这些选择。

需要区分三个东西：

- **官方包默认**：dropc=.4，min_count=10000，recompute=10000。
- **论文特定任务配方**：Gigaword用了c=.6，原任务的hot-start也远长于本轮训练。
- **我们实际测的任务适配**：开发扫描c∈{.01,.05,.1,.4}，固定预热及迁移使用选出的.05；窗口／重算160，固定20／50／100／150步或gate预热；总训练1250步。

官方代码先加入当前loss再计算／使用阈值；本地先从过去缓存算阈值、筛当前批、再加入当前loss。官方类只返回mask，具体训练归一化还由调用方决定；不能只看dropper类就断言所有原版训练归一化。

窗口缩短有“让1250步训练及时反应”的理由，但**没有原版与适配版的直接结果，不能断言改动必然有利于LT**。也不能断言两版效果一样。当前25次LT运行里没有10000/10000完整对照。

固定20／50运行时不依赖Curfew gate；但c=.05来自gate对齐的开发扫描，所以仍应披露开发来源。LT+gate单列为混合／消融，不能和独立固定LT混成一个原版。

官方来源：[LT论文](https://aclanthology.org/2020.acl-main.66/)、[LossDropper源码](https://github.com/ddkang/loss_dropper/blob/master/loss_dropper/dropper.py)。

### GraCeFul：需要更名并纠正成本归属

结合原论文与作者公开实现，流程是：**基座模型上逐样本抽lm_head梯度 → 2D DCT → 保留1/64低频 → PCA32／标准化 → 余弦平均连接层次聚类 → 删除小簇 → 正常微调一次**。其中标准化与平均连接的具体选择来自作者代码，不能仅归为论文正文所写。

我们的流程是：**先训练污染A1 → 在端点抽解析梯度随机投影 → 谱分数或PCA10／2-means → 标签oracle选预算 → 从头重训**。这同时改变了阶段、特征、聚类和决策规则。

建议将现有结果名称改为“端点随机投影梯度过滤＋重训（受GraCeFul启发）”。旧记录保留，但本文撤回把约1,160秒、2.2倍端到端开销归给原生GraCeFul的说法。原生GraCeFul仍有自己的全量梯度提取及聚类开销，**具体多少目前不知道**。

来源：[原文Fig.2、§4](https://arxiv.org/html/2412.02454v1#S4)、[作者实现](https://github.com/ZrW00/GraceFul/blob/main/openbackdoor/defenders/graceful_defender.py)。

### DeCE与GradSentry：不能把配方变化藏在方法名后面

DeCE存在公开论文／代码默认不一致：论文α=.99、ε=.1；官方README核心代码α=.985、label_smoothing=.05。本地的.985/.1混用了两者来源，并把20次完整epoch的指数进度压成一次训练中的连续进度。α=.985有官方来源，不应说成凭空发明；但sched20也不能叫“原版20epoch配方”。本地平滑沿论文ε/V，官方README沿非目标ε/(V−1)，二者还需分清。[论文§4、§5.3](https://arxiv.org/html/2407.08956v3)、[官方仓库](https://github.com/NTDXYG/DeCE)。

GradSentry本地既测literal H/log16，也测我们增加的H/log(min(16,T))。相同AUROC不能保证自动阈值等价；本地KDE固定网格、峰高判断和官方当前的峰prominence、观测范围网格、多项可靠性条件并不一样。固定5token答案又使梯度低秩结构特别明显，所以它是需要分析的短答案边界，不能直接判原法无效。[论文](https://arxiv.org/html/2605.26574)、[官方实现](https://github.com/dongdongzhaoUP/GradSentry/blob/main/openbackdoor/defenders/svd_defender.py)。

## 5. 原设计的哪些“公平”承诺尚未落实

| 原设计或旧汇报说法 | 审计后应采用的表述 |
|---|---|
| 7类都经过oracle调参、预算对齐和正向对照 | 不同组完成程度不同；只有ABL明确有本地前置投毒隔离阳性结果，其他原任务阳性凭证未找到 |
| SS、AC、GraCeFul各自完整跑过 | SS／AC在base_repr、endpoint_repr池中oracle择优；endpoint_repr未晋级重训；梯度组不是原生GraCeFul |
| 端点特征需前向＋反向 | 实际T1用no_grad＋解析梯度，一次前向联合提loss、hidden及gradient sketch |
| 每个原方法有独立时间 | T1的done.seconds是联合抽取耗时，不能直接当成各官方方法单独耗时 |
| 任一≤5%预算残余≤20就晋级 | 实际代码另要求至少2个seed满足；endpoint_repr只有1个seed满足，未进入T2 |
| oracle一定“对对手有利” | 标签oracle给了额外信息，但算法改造本身未证明有利；检测召回最优也不一定是最终ASR／质量／成本最优 |
| toy失败即可不进入真实主比较 | 只能作为当时节省预算的筛选；不能因此宣称已击败该方法在真实任务上的表现 |
| 同预算就是所有方法必须删同样多 | 删除量匹配是补充消融；不能替换原生自动阈值、整簇删除或原生训练课程 |

统一固定1250步、将删行改成原位置mask而不压缩数据／重排epoch，有控制训练流的好处，但也是任务协议改造，应与原生配方区分。

此前“Accept下限→补实验冲Strong Accept／Oral”的依据包含“补齐强baseline后仍领先”这个条件。现在固定LT打平，且若干方法尚未原生比较，**原先档位判断不能继续作为当前结论**。这不证明所有机制问题都无价值，也不提供新的录用等级保证。

## 6. 参照Han Lab的比较原则，重新列公平方案

下面是从公开论文中能核实的做法推导的方案，不是声称Han Lab有统一、公开的baseline操作规范。

- **SmoothQuant** §5.1／Table2把不同量化粒度、动态／静态及混合精度写清；Table3还保留了ZeroQuant较强的FP16注意力输入尝试。Appendix A解释weight-only GPTQ在实现／场景上的比较边界；§5.3区分PyTorch与FasterTransformer系统结果。[论文](https://proceedings.mlr.press/v202/xiao23c/xiao23c.pdf)
- **AWQ** §5.1同时比较简单RTN和GPTQ／GPTQ-Reorder，并对齐位宽及group size；算法精度和系统后端性能分别分析。它支持纳入强简单对手，没有给“逐测试seed用标签oracle选最好参数”背书。[论文](https://arxiv.org/html/2306.00978v5)
- **SparseRefine** §4.2比较token pruning、mask refinement、patch refinement等不同机制，围绕共同任务的精度和延迟终点比较。机制不同本身不是排除理由。[论文](https://arxiv.org/html/2407.19014v1)

据此建议采用以下规则；此处仅制定方案，不执行。

### 6.1 两种“原版”分清，并保留两个配置栏

**官方原任务复现锚点**：对核心方法选一个作者明确公布的代表设置，确认官方代码流程和效果方向可复现；不要求重跑整篇论文。没有通过先查实现、版本、数据和假设，不能当成方法失败。

**官方实现迁移到共同任务**：同一基座、同一污染数据／攻击、同一评测；只做必要tokenizer、输入／输出接口迁移，保留原算法阶段、损失、阈值、聚类及训练课程。所有接口迁移逐项记录；尤其验证loss单位／归一化、梯度模式、缓存顺序、mask与数据压缩差别。关键接口应做同输入输出对照。

主比较保留两栏：

1. **官方实现／作者推荐配方迁移**：版本、配置与必要变化可追溯。
2. **当前任务开发集适配**：开发预算与可调参数事先固定，独立列出，不覆盖第一栏。

直接把原论文在别的模型、攻击、投毒率上的数字搬来与我们的数字横比，不能得到谁更强的结论；原论文数字适合作为复现锚点或单列参考。

### 6.2 比最终任务，也明确资源条件

共同主终点是防御后的ASR、正常任务能力、新知识学习能力及完整成本。共同数据／威胁模型要固定：训练集、投毒率、触发器可见性、顺序／阶段、基座revision、评测集合与评价方式。

- 使用干净辅助数据的方法：MuScleLoRA、CROW。写明样本数量、来源和使用次数；若主张所有方法在同一辅助资源预算下可用，应给我们和其他适用方法同等访问权限。
- 使用额外任务参考模型的方法：RFTC。计入参考模型身份、可信假设、推理／生成成本。
- 使用真实毒标签、已知触发器，或事后读取另一条同seed Curfew运行时机的版本：仅作oracle／额外信息对照，不进入未知触发器的独立主baseline排名。
- 自行在线按训练loss计算gate的冻结LT+gate无需攻击真值，属于可部署混合基线，应单独命名并可以进入部署效果比较；不能与事后读取gate的oracle混为一谈。

“读取内部梯度”不自动等于知道更多攻击真值，不能笼统写成“对方信息更多，所以一定对它有利”。对有额外资源的强方法仍展示终点效果，分组说明不应成为回避正面对比的理由。

### 6.3 控制调参选择，不制造新的cherry-pick

- 先固定开发与测试边界；本轮已反复查看的seed／测试结果用于探索，不能再次宣称从未见过的确认性测试。
- 每种方法有作者默认／推荐配方锚点；额外调参只用开发数据，给出事先声明的可比预算，记录全部尝试、失败和选择规则。
- 一套开发选出的规则迁移到后续seed／设置；不逐测试seed挑c、层、方向、阈值或删除量。
- 投毒真值可以用于事后算检测召回，不能用于主实验选删哪些行或选最优预算。oracle曲线可保留，明确它不可部署。
- 不仅展示最好值：每seed配对结果、成功数／总数、离散程度、适用性失败都保留；对小样本不夸大稳定性。
- 不能只让原版默认失败来衬托我们，也不能用自行改造过的劣化版本代替原方法。

### 6.4 保留原生流程，成本逐段算

不强迫所有方法同样删除量、同样1250步或同样epoch。先评价它们自己的完整有效流程，再给成本相近的补充比较。否则把需要完整训练课程的方法压成一轮，是改了方法。

- 训练前过滤：打分／抽特征＋聚类＋一次过滤后训练。
- 端点修复：污染训练＋修复；若采用“已有端点模型”场景，所有方法按同一沉没成本定义另表说明。
- 中间或端点筛选后重训：第一遍训练＋打分＋第二遍训练。
- 在线方法：本次完整训练＋实际附加开销。
- 另报开发／调参总成本，不能只计被选中的单次配置。
- 同时列总GPU时间、墙钟、峰值显存、额外数据／模型、删除量；联合特征抽取计时和GPU共跑的墙钟不能冒充各方法独立部署延迟。
- “少一次额外前向”或“防御额外1秒”不自动等于端到端快1000倍。

现有ASR／质量结果继续按原评测定义保留；其中固定候选答案比较、5token toy、124题及TOFU NLL学习增益的边界要明确。TOFU NLL增益不是回答正确率，受限候选评测也不是完整自由生成安全验证。

## 7. 强防御要不要加：要，但按任务和证据选，不按名字凑数

这里的“强”意为已有相关任务证据、方法具有竞争力且可核验，不代表所有候选已被证明在我们任务上最强。

| GraCeFul | 只有实质不同的端点代理 | 原生生成式FSQA／LoRA；训练前梯度过滤，不需额外clean集 | **最高优先修补身份和效果证据缺口** |

### 当前讨论优先级，不是新实验队列

1. **先纠正身份和主张**：用本报告给现有适配版正名，撤回不支持的官方失败、成本归属及录用档位保证。此项是当前审计已完成的工作。
2. **先决定还要主张什么**：如果目标仍是“更好的通用防御”，固定LT打平就不能回避，真正相关的不同机制强对手也必须进比较；若只讨论现象／机制，需要独立可证伪的机制命题，不能靠弱baseline替代贡献。
3. **若之后决定继续防御方法比较**：第一批候选范围为固定LT、官方GraCeFul／GradSentry的保真流程、配方审清的DeCE；其中先选最关键少数完成可信比较，不同时铺开所有名字。当前不分配GPU、不发起任务。
4. **扩大部署主张时再扩权限和机制**：考虑生成式CUBE；若要声称最终部署收益，再加入CROW等修复代表，并列明clean成本。RFTC／MuScleLoRA由允许资源与论文主张决定。

判断标准很直接：如果可信强方法在相同任务下以相近或更低总成本稳定打平，防御方法优越性的主张就应缩小或撤回；这与是否存在独立的机制发现是两回事。当前不能预先保证“补上这些仍会赢”，也不能用旧toy筛选结果替代尚未完成的真实原生比较。
