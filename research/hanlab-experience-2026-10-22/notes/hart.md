# HART: Efficient Visual Generation with Hybrid Autoregressive Transformer

## 0. 元信息
- arXiv 2410.10812v1（2024-10，"Preprint, work in progress"；后发表于 ICLR 2025）。MIT/NVIDIA/清华。
- 类型：算法 + 少量系统优化（混合 tokenizer、VAR 式 AR 变换器 + 残差扩散 MLP、kernel 融合）。
- 文本状况：全文含附录读完，表格清晰。Fig.7 曲线只能读出标注点（MAR 30 步 IS 271、60 步 280；HART 6 步 313；分离解码器 24K 步 FID 21.98 vs 单解码器交替训练 5.30）。

## 1. 核心主张
- 主：AR 模型（732M）可直接生成 1024px 图像，质量与扩散模型相当（MJHQ FID 5.38、CLIP 29.09），同时吞吐高 4.5–7.7×、延迟低 3.1–5.9×、MACs 低 6.9–13.4×（Fig.1, Tab.2/3）。
- 次：(a) 混合 tokenizer（离散 + 连续残差）把 1024px rFID 从 VAR 的 2.11 降到 0.30，与 SDXL tokenizer 相当（Tab.1）；(b) 残差 token 比 MAR 的完整连续 token 易学得多：8 步 vs 30–60 步（Fig.7 左）；(c) 单解码器交替训练优于分离解码器（Fig.7 中/右）；(d) 相对位置编码使分辨率迁移收敛更快（Fig.8）；(e) 类条件 ImageNet 上优于 MAR-L 且快 12.9×（Tab.4）。

## 2. 动机是怎么立住的
- 痛点用 MACs 量化：DiT-XL/2 20 步 1024px 需 86.2T MACs，同规模 VAR 仅 10.1T（8.5× 少）（§1）——用理论计算量论证"AR 有效率潜力"，再指出两个阻碍：离散 tokenizer 重建差、无 AR 能直接生成 1024px。
- 关键可视化：Fig.3 把一张图拆成"离散 token 解码 + 残差 token = 最终图"，直观展示残差承载眼睛、头发等细节；Fig.4 展示 VAR tokenizer 在人脸细节上的丢失。这是"把方法的分解本身画出来"的说服方式。
- 设计依据：Tab.1 证明重建上限（rFID）已接近扩散 tokenizer → "生成上限与扩散模型一致"。作者也主动提醒 "low rFID does not necessarily indicate better generation FID"（§3.1 Discussions），并用 Fig.7（分离解码器 rFID 相近但 gFID 21.98 vs 5.30）证明——这是对自身论证漏洞的预先封堵。

## 4. 实验设计手法
- 基线：扩散与 AR 两类都覆盖；速度"使用作者推荐采样参数"自测（§4.1），并对 SDXL、PG2.5 同时给出两个步数设置（Tab.3）——主动展示基线的更快配置，增强公平性。AR 基线包括 LlamaGen、Show-o，**未包含当时同期的 1024px AR（Lumina-mGPT）的数字**，仅在相关工作中声称"效率更优"。
- 朴素基线：HART-VAR（去掉残差扩散，Tab.5），且作者承认"用公开 VAR 代码复现的离散基线略低于原论文"——透明但也意味着基线偏弱。
- 规模：类条件三尺寸（d20/24/30），T2I 一个尺寸；三个分辨率。
- 效率测量：A100 实测延迟/吞吐 + MACs，三者并列；指出与 PixArt-Σ 的实测吞吐比（5.6×）与 MACs 比（5.8×）吻合——用"实测与理论一致"增强可信度（§4.2）。
- 精度–效率联合：Fig.1 CLIP vs 吞吐柱状；Tab.4 同表 FID 与 MACs/时间。
- 消融：残差扩散（多分辨率、多尺寸，Tab.5）、tokenizer 训练策略（Fig.7）、PE（Fig.8）。
- 分析性实验：注意力模式可视化"sink + local"（App.A.1, Fig.9），用于解释为何训练时丢 80% token 无害，并声称"限制为前 3 阶段 + 局部 2 阶段注意力不影响结果"（无数字）。
- 泛化：类条件 + T2I；tokenizer 在训练未见数据集上评测。
- 统计：无。
- 系统贡献：开源代码、在线 demo、kernel 融合。
- 局限：无。

## 5. 对抗式审读
- **头条 31% 的基线选择**：摘要"gFID 7.85→5.38（31%）"中的 7.85 是"官方 VAR 量化器"（Tab.5 ∗ 行）；同表用 HART 自己的离散 tokenizer（同样去掉残差）是 5.73，残差扩散的真实贡献是 5.73→5.38（6.1%，正文承认）。摘要把 tokenizer 训练改进与残差扩散的收益合并计入。
- "与扩散相当"偏宽松：GenEval 0.56 低于 SD3-medium 0.62，DPG 80.89 低于 SD3 85.80；领先主要在 MJHQ FID——而训练数据含 JourneyDB 与"内部 MidJourney 风格合成数据"，MJHQ-30K 本身是 Midjourney 图像，FID 优势可能部分来自分布匹配（论文未讨论）。
- 类条件对比 MAR 用 64 步、DiT 用 250 步（113s），这些是对手的默认最高质量配置；"比 DiT 快 3.3×（即便 DiT 用 20 步）"一句在表中无对应数据。
- 训练 token 丢弃、kernel 融合收益只有文字。
- Tab.5 中 1024px 的 Time（25.9/28.7s）与 Tab.3 的 0.75s 量纲/批量不同但未说明，残差扩散的真实开销比例需要读者自行推算（约 11%）。

## 6. 可迁移手法
1. 把"分解"本身可视化（离散部分 + 残差部分 = 最终结果），让读者一眼看懂每部分负责什么（Fig.3）。**直接读到**
2. 预先承认"重建好 ≠ 生成好"，并构造一个"重建相近但生成差很多"的反例来证明自己的训练策略不可替代（Fig.7 中/右）。**直接读到**
3. 效率表同时给延迟、吞吐、MACs，并指出实测加速比与 MACs 比一致（Tab.3, §4.2）。**直接读到**
4. 基线给多个步数配置（SDXL 20/40、PG2.5 20/50），避免被说只选了慢配置（Tab.3）。**直接读到**
5. 用注意力图（sink + local）为一个训练加速技巧提供机制解释（App.A.1）。**直接读到**
