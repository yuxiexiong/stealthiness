# 第 4 步：BAIT 在我们设置上的适用性（未运行）

结论：**没跑。按 BAIT 的算法，我们的单词目标在结构上测不到，照原样运行只能产生"没检出"，那不是证据。** 依据是子代理读的仓库代码与 S&P 2025 论文，不是我们自己的运行。

| 障碍 | 出处 | 影响 |
|---|---|---|
| 候选目标必须 ≥4 个词（min_target_len=4） | 代码 | violin 一词直接被丢弃 |
| Q 分数是目标第 2 个 token 起的平均概率，首 token 不计 | 论文 Alg. 1 + 代码 | violin = vi + olin，Q 只剩 P(olin\|vi) 与 P(结束\|violin)，几乎任何以 vi 开头的词都高分 |
| 候选首 token 只取带前导空格的字母 token | 代码 | 我们的答案在思考块之后无空格开头，真首 token "vi" 可能不在候选集 |
| 必须调用 GPT-4o 判"是否可疑" | 代码 | 要把模型输出发给外部服务；violin 无害，会被判安全而丢弃 |
| 依赖 transformers 4.44 | requirements | 不能加载 Qwen3（需 ≥4.51）；服务器 amic-q3 环境可绕过，但作者未测 |
| 论文中所有目标 5–20 词或整句；1% 投毒只在自适应攻击表中出现（攻击本身失败） | 论文 | 无同条件先例 |

改掉词数门槛、绕过判官，就成了另一个方法，跑出来不能叫 BAIT 的结果。

含义：事后检测加回滚这条防御路，**承重件在单词目标上目前没有现成可用的检测器**。这不否定这条路，但它的第一步变成"找到或造一个对短目标有效的事后检测器"。手头最接近的线索是干净提示上的目标泄漏（MARGIN_REREAD §4）：终点时单一目标的 A1 在无触发提示上 violin margin 比 A0 高约 6.5，但分散目标下几乎消失。
