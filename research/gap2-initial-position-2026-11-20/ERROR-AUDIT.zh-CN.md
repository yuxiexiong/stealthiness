# M058 过零规则的误差来自哪些近似？

**在 KK 的三条 P 臂上，代入干净对照的实测终点位置，找回的原漏报都比只代入实测 P−K 分数差多。** 代价随输入而变：P1 没有新增错误，但 P2 和 P3 会把部分原先判对的题改成误报。这个窗口对“把 K 臂当作停在起点”这一近似给出了具体反例。

## 原来错的题能找回多少，原来对的题又错了多少？

每个单元格的整数或范围来自该行 P 臂与三个 K 臂的逐一配对。原漏报是完整生成中仅 P 命中、主规则没有选中的题。新增错误以各自原配对为基准。不同配对会重复使用同一道题，范围端点不代表不确定性区间。

| 前史 / 输入 | 原漏报 | 修正 K 位置找回 | 修正 K 位置新增错误 | 修正 P−K 分数差找回 | 修正 P−K 分数差新增错误 |
|---|---:|---:|---:|---:|---:|
| KK / P1 | 28 | 10–14 | 0 | 1–2 | 0 |
| KK / P2 | 8 | 7 | 3–7 个误报 | 0 | 3 个漏报 |
| KK / P3 | 7 | 6–7 | 4–8 个误报 | 0 | 3 个漏报 |
| RR / P1 | 1 | 0 | 0 | 0 | 0 |
| RR / P2、P3 | 各 0 | 0 | 0 | 0 | 0 |

两种修正是否找回同一道题，在 P1 上尤其重要。KK / P1 配 K1、K2、K3 时，各有 1 道原漏报可被任一单项修正找回；各有 16、14、12 道只有联合代入才恢复判对。每个配对还有 2 道原漏报在联合代入后仍未判对。KK 中每个配对原有的 1 道误报都被 K 位置修正消除；表内新增误报是其他题。RR / P1 的 1 道原漏报在三种配对中都只有联合代入才判对。

## 实际比较与判读边界

在每个前史的 200 道固定题上，记 t 为起始首词分数，k 和 p 分别为同题 K 臂与 P 臂第 330 步的分数。a 沿用第一阶段冻结值。对任意两臂假设分数 (u,v)，用 u≤0 且 v>0 判断“仅 P”。四种代入依次为 (t,t+a)、(k,k+a)、(t,t+p−k)、(k,p)。行为真值始终取真实生成的“P 命中且 K 未命中”。

联合代入逐题还原真实终点分数，只作算术与评分核对。联合代入后剩余的错误均涉及终点平局。重叠表中的 unresolved 指三种替换均未修复的原错误。它与联合代入的全部残余不同：KK / P3 配 K2 时，单换 K 位置找回全部 7 道原漏报，联合代入却仍漏 1 道平局题。两项替换都用到了同一 K 终点，批间与题间差异也同时存在；“只有联合代入才判对”不能识别训练中的因果交互。此次结果说明在哪些固定输入上哪项近似失准，不能把第一阶段少算的 13 题分配为两个独立原因。

## 核验与复现

核对原冻结预测的 SHA-256、18 个原配对的重合/误报/漏报题号及关键计数，再检查每个替换下的错误数收支、原错误去向分组和联合代入等式。两段前史各有 3×3 个组合，共 3,600 条题目×组合记录。属于一套固定数据的重复比较。本次只使用 CPU 读取已有归档。

在本目录或完整归档解压目录内运行 `python3 audit_errors.py --out replay-errors`（输出目录须尚不存在）。[逐配对比较](error-audit-results/comparisons.csv)包含每个单项替换消除和新增的误报、漏报数。[错误的重合与分流](error-audit-results/overlap.csv)列出单项、联合及未恢复的原错误。[逐题表](error-audit-results/items.csv)保留题号、真实生成标签、两个终点平局标记、起始正分标记与四个逐题判定，可按每组的题号核对哪些题改变。

独立 Advisor 用 3,600 条记录重建四种判定，核对了 72 行修复/新增计数、36 行分流与预测哈希。已采纳关于平局和 unresolved 定义的修正。独立解压第一阶段归档重放，三张新结果表均逐字节一致。向测试副本注入错误的冻结文件后，仅生成失败报告。
