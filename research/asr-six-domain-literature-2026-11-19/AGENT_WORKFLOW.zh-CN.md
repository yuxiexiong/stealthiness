# 全文查重与 SubAgent 使用方法

适用：围绕一个科研主问题，按领域查明已有工作、实质重合、反证及证据边界。本文整理本次已经采用的流程及节省重复工作的操作约定；不是新的实验授权，也不是新的研究结论。

配套文件：[执行协议](PROTOCOL.md)、[当前任务状态](STATUS.md)、[六域报告入口](README.md)。本次未全部完成，不能将流程说明当作审查通过证明。

## 1. 开始前只明确必要信息

主 Agent 写清：主问题、每域包含/排除范围、检索截止日期、与本项目比较的已知证据，以及完成条件。已有协议和证据索引直接复用，不在每次交接重新审计项目历史。涉及实质研究方向或实验设计时，按项目约定咨询 Advisor；普通查重记录、修订和上传不因此增加审批环节。

每条线索必须有归属。跨领域论文指定一个全文主读者，其他领域回查支撑自身结论的原文段落；标明“他域全文主读、本域相关节核读”，不把它算成自己又全文阅读了一遍，也不重复计算为独立证据。

## 2. 四种职责，三名独立领域 SubAgent

| 角色 | 负责 | 不应代替的工作 |
|---|---|---|
| 主 Agent | 定范围、分派、维护状态、处理跨域接缝、合并报告、控制重复开销 | 不冒充独立 B/C，不用自己的补写代替要求的审核 |
| A：查重作者 | 检索、全文阅读、证据定位、写报告、按 B/C 意见修订 | 不自行宣布独立 review 通过 |
| B：原文 reviewer | 对全部实质主张回原文核验，提出更正并复核修订 | 不只抽查几篇，不因作者说已改就通过，不默默代改作者结论 |
| C：独立查漏者 | 先独立发现候选，再对照 A/B；查漏文献、结果、反例、术语体系及领域交界 | 初次检索前不看 A/B 清单，不以“没有搜到”证明新颖性 |

一个领域的 A、B、C 必须是不同 Agent。返工交回原 A、原 B，再回原 C，避免不断换审查者直到有人认可。主 Agent 不必为每个句子另开 Agent。SubAgent 不递归创建下一层审查者。

## 3. 正确顺序

`A 全文查重 → B 原文 review → A 修订 → B 复核 → C 独立查漏`

- B发现错误：原A按问题编号修订，原B只重核改动、受影响的结论及新主张。
- C发现重要遗漏：原A补原文、修报告，原B核新增内容，原C复核遗漏分支并补查。没有固定轮数配额。
- C发现只是已有结论的同类补例：写清对应关系或加短链接，不自动触发整个领域重跑。
- 新材料会改变“已做什么、适用范围、因果解释、关键反证”才是实质缺口；不是每个新标题都阻断结束。

不同领域可以并行，领域内保留上述依赖顺序。先安排有实际工作可做的角色，不启动一批只能等待前置材料的 Agent。

## 4. 检索与全文阅读

覆盖四条路径：最相关原始研究、最新及低引用研究、相关综述、前后向引用链。记录实际检索入口、查询、日期、关键命中及去向。综述用于找原始来源，其“未来工作”不代表今天仍是空白。改名、不同领域用语及反向结果都要查。

摘要可用于初筛。纳入实质结论的主读者须读完整正文及相关附录/补充，并核身份和版本。图表、公式提取不清时回PDF原图；下载、搜索命中、只看首段均不等于全文已读。

每项重要证据至少记录：稳定ID/版本/官方链接、实际阅读范围、页节图表、模型与数据、训练操作和对照、指标及分母、结果/反例、不能推出什么。区分作者解释、条件理论、受控干预、相关观测和本报告推断。终点成功、完整输出、代理概率、运行时拦截、参数删除不互相替代。

公开全文不可得时，尝试合法的出版方、作者、会议或预印本入口。不能用摘要补成正文结果；缺附录也要单列。没有专业数据库访问就如实写实际工具，不能声称完成了该数据库检索。

## 5. B 与 C 的验收方式

B按“主张 → 原文页节 → 判定 → 更正要求”记录，覆盖所有影响已有工作和重合判断的实质主张。可以把同一实验的相关句子合并成一组，不必逐字复读已核无改内容。具体数学错误须有原式和理由；没有重推定理就不声称完成证明验证。

C首次只收协议与领域边界，自行检索并保存 `C_INDEPENDENT_SEARCH.md`，明确记录候选阶段已冻结，之后才打开A/B材料。后续轮次不假装重新盲审，只补查新增分支和先前缺口。每个候选说明：已覆盖、重要新增、跨域归属、范围排除、或来源受限。

有界结束要求：声明范围与日期内规定路径已走过；重要线索都有处置；支撑结论的全文和B核验完成；C末轮没有发现会改变判断的重要未处理遗漏。核心来源缺失则明确“受来源限制”，不能写成无条件查干净。未找到先例不等于认证创新性。

## 6. 文件及状态

| 文件 | 用途 |
|---|---|
| `REPORT.md` / `REPORT_A.md` | 当前报告 / 初稿快照 |
| `PAPERS.json` | 文献ID、版本、URL、阅读状态、原文定位、本地缓存路径等 |
| `SEARCH_LOG.md` / 阅读笔记 | 实际检索与证据记录 |
| `B_REVIEW.md` / `REVISIONS.md` | 审核问题、作者逐项处置、复核结论 |
| `C_INDEPENDENT_SEARCH.md` / `C_AUDIT.md` | 初次独立发现、查漏与后续轮次 |
| `STATUS.md` / `shared/CROSS_DOMAIN.md` | 当前角色/阻塞/下一步，以及跨域主责和交接 |

状态必须分开：未读、正文/相关附录已读、仅相关节核读、来源受限、待B、B需修订、B核准、待C、C需补查、有界完成。命名可沿用已有索引，不要求为此重写所有历史记录。保留失败、撤回和未完成，不只保留最终成功。

## 7. SubAgent 调度操作

以下是本次会话工具的用法约定，不是假定所有环境都有同名API或相同并发数。先检查当前可用工具/Agent状态；本次并发上限曾为主Agent加3名活动SubAgent，以运行时限制为准。

- `spawn_agent`：首次建立A/B/C；使用独立上下文（本次为 `fork_turns="none"`），发送最小任务包与文件路径。不要复制全部对话和整份报告。独立上下文仍不等于独立模型、独立复现或人类专家认证。
- `followup_task`：原角色结束后，给它具体返工或复核任务；保留原编号和原材料，避免重启成新的泛泛查重。
- `send_message`：给正在工作的角色补充必要事实或交接，注明“已全文核实”还是“仅发现候选”。不要把发送消息当作接收者已经完成阅读。
- `list_agents`：必要时查运行/完成/错误状态。收到完成输出后再占用空槽，不高频轮询或反复失败地启动。
- 等待/通知：工作完成、出现实质缺口或阻碍时汇报；状态问题按完成阶段回答，不虚构百分比、剩余轮数或token预算。

Agent跨会话不能保证仍可用。失效时从原协议、报告、问题编号和日志恢复角色，并明示是重建，不能声称它记得上一轮。只把必要路径和未完成事项带入新上下文。

## 8. 控制 token 和返工范围

先复用后新增：复用论文缓存、主读分工、已有原文定位与已关闭审查项。B复核修订只读差异及相关上下文；C复核只追新增或未闭合分支，不重复完整盲搜。主Agent不再作为第四个 reviewer 把所有全文读一遍。

任务包只包含：角色与范围、必读路径、未关闭编号、输出位置、验收条件和权限边界。回报只包含：完成了什么、重要发现、输出路径、未完成事项。长证据留在文件，不在主对话和每轮交接重复粘贴。

用户明确给预算才记录预算；没有真实统计就不声称掌握精确token账单。预计继续工作会扩大范围时先说明实际取舍；不通过偷换“全文”为“摘要”节省成本。遇用量上限或工具不可用，保存已核项/未核项，不循环重试，不伪装B/C完成。

## 9. 可直接复用的短任务模板

**A首轮：**
> 负责领域{范围}。读{协议路径}，按四类检索路径查重；主干正文全文及相关附录须实读。写REPORT、PAPERS、检索/阅读日志到{目录}。每条实质结论给原文定位、条件与反证。不得递归委派、运行实验或发布。简短报告结果与未完成项。

**B首轮：**
> 独立审核{REPORT路径}。逐项核全部实质主张的原文，不抽查。写B_REVIEW，给问题编号、证据位置和必要修订；不代改A。缺口按会改变的结论解释，不机械扩目录。

**C首轮：**
> 只先读{协议与范围}；独立检索并冻结C_INDEPENDENT_SEARCH后，才读A/B材料。重要新增须全文核实。写C_AUDIT，区分重要缺口、已覆盖、跨域、排除与受限。符合有界条件才能结束；否则交回原A/B。

**A返工 / B复核 / C复核：**
> 只处理{问题编号}及受影响结论，参照{意见路径}。更新对应文件，保留历史。已关闭无改内容不重跑；新增主张仍须原文支撑。输出修复/未修复及理由。

## 10. Git归档与本次继续方式

上传原创报告、索引、审查及修订记录和本说明。下载的第三方PDF、全文提取、页面截图、源码包作为本地缓存；本次未随报告上传。索引里的 `fulltext_path`/哈希保留为本地溯源信息，远端缺少该缓存不等于未阅读。换环境续接时通过索引官方URL重新取得对应版本；不能把URL存在当成已复核。

提交前核报告状态、JSON结构、选定文件与秘密信息；只提交任务目录，避免卷入工作区其他修改。上传当前阶段不等于合并到主分支，也不等于研究审查完成。当前六域的具体未完成项以[STATUS](STATUS.md)为准；本次用量中断后不自动启动新查重或新实验。
