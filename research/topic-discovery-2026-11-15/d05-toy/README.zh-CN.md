# D05 实现准备：改变名称划分，观察污染错误覆盖

2026-11-15。**本目录是实现准备，不是实验结果，也不表示已获启动许可。** 已完成的数据/指标检查只使用Python标准库；本轮没有创建研究模型、前向、训练、资格前缀、GPU测速或远端实验操作。

科学设计见[已审设计](../D05_TOY_DESIGN.zh-CN.md)。两个名称写法的合法含义均先提供干净学习机会，再保持题目、污染监督和训练顺序一致，比较完整名称与共享部件名称的错误。本轮不改剂量、种子数、终点、模型规模或主指标；Advisor发现原绿色条件仍可能被失格块抬高幅度，已追加结果前的解释支撑条件，详见下文及设计第7节。不把成熟的分词/共享特征方法说成首创。

## 实际准备了什么

- `data.py`：五块固定数据、相同的内容分层表、随机ID、W/P可逆编码、P8/P16及20轮配对顺序和位置表。
- `run.py`：明确分开的仅数据准备入口和未来执行入口；先五个干净前缀，资格够才六分支；固定模型/优化器，保存全部读点和状态；失败停止，不自动重试、延长或换种子。
- `metrics.py`：原始ASR/正常能力/连续margin及E/G/S/I，按实际n块计算，检查同一组块的解释资格和效应，保留双读入交互。
- `test_preparation.py`：确定性CPU数据和人工预测反例测试，不把模型训练藏进测试。
- `estimate.py`：完整计数与未测速的耗时情景，不调用模型或GPU。
- `audit/`：代码身份、数据哈希、CPU测试记录与预算。完整原始manifest可由固定代码重新生成；哈希核准后使用。大体积顺序表不靠人工复制维护。

主任务Q在代码中用0…3索引对应设计中的第1…4开关；辅助Q仍为0…7。它只是无语义ID的双射重标记，不是任务改变。辅助评估每名称每侧8个不同问题：正例1、负例7，计算正负等权准确率；训练重复正例7次以平衡监督。3072评估行=2048 ROUTE+512 LEFT+512 RIGHT。

## “有没有把结论写进编码”目前能检查到哪一层

1. **两种格式均可还原相同题目和名称。** 全部五块34,560原始行×三种读入=103,680次往返；改truth/poison/target/id不会改变输入。正确开关在题目里是合法内容，答案标签没有额外输入槽。
2. **名称不偷偷绑定正常答案。** 每个名称用完全相同的(q,x)训练/评估表，每个(q,truth)格4条；每格训练/评估互斥。近邻和远邻不会因换名而换了一套更难的题。
3. **改标签之外不额外帮某个分支。** P8严格包含在P16中，8条按q平衡；只改目标名称的ROUTE真0行，全部辅助任务保持正确。各分支原始行顺序与批边界一致，W位置每行20轮各占10次，不由标签决定。
4. **没有强迫模型按部件相加。** 模型是普通非线性Transformer，整名embedding独立初始化。编程中没有“共享部件就必须输出1”的规则。正常辅助任务给两格式都学习部件含义的机会。
5. **判读不只奖励一个方向。** 人工构造的正向、负向、读入反转、异质相消、资格/效应不在同一批块、缺失读点和全答否反例用于检查指标。不能靠绝对值平均或事后删块过关。

这些检查排除了明确的输入泄漏、硬编码答案和已测试的统计实现错误，**没有证明所有归纳偏置相同**。W/P活跃词项数、频率、位置和内部组合难度仍然不同，这是本轮总操作的一部分。共同前缀能否真正让两种格式都熟练、分支起点参数/逐题logits是否完全相同、PyTorch运行时和梯度是否正确，目前未运行验证。它们是未来执行中的硬检查/科学资格，不能拿CPU数据通过来替代。

还保留三项解释限制：辅助任务是熟悉字典探针；资格集与最终测量集复用，不是独立确认；G/S不能完全排除整体logit偏移在不同初始margin上的阈值效应。每题两类logits和概率都会保存，不能只凭ASR差说已识别部件传播机制。

## 准备与未来执行入口

当前允许重复的确定性检查（在本目录）：

```sh
python3 -m unittest -v test_preparation.py
python3 estimate.py
python3 run.py --prepare /tmp/d05-prepared-NEW
```

`--prepare`只导出数据、配置、代码哈希，不import torch。输出目录必须不存在。没有默认运行行为、后台进程或队列。

以下仅记录未来获用户明确执行授权后使用的接口，**本轮未运行**：

```sh
CUDA_VISIBLE_DEVICES=<one-physical-GPU-id-or-UUID> python3 run.py \
  --execute /path/to/NEW-run-directory \
  --manifest /path/to/reviewed-preparation/manifest.json --device cuda:0
```

依赖为Python、PyTorch及其模型哈希所需NumPy；不包含自动安装。当前本地Python3.9.6未安装torch。未来须记录并固定实际环境；代码显式FP32、禁TF32、启确定性算法，不能承诺跨软件版本/设备逐位相同。[PyTorch复现说明](https://docs.pytorch.org/docs/2.15/notes/randomness.html)

执行入口先核数据/源码身份、重跑标准库检查，再只读检查单卡隔离、空闲进程、显存和盘空间；不杀进程、不排队。查询得到的物理GPU UUID在import torch前绑定为唯一可见设备，避免CUDA与nvidia-smi数字编号顺序不同。这个瞬时检查不提供跨进程资源租约，未来执行仍需外部资源隔离。每分支重新建立空优化器并复制同一父权重与RNG，参数字节哈希和三种读入全部logits哈希不符即停。模型采用官方`TransformerEncoderLayer`的pre-LN、batch-first等参数，接口核读不是模型运行验收。[官方接口](https://docs.pytorch.org/docs/2.15/generated/torch.nn.TransformerEncoderLayer.html)

初始点和每轮末点都保存完整状态、逐题压缩JSONL和摘要。单次故障保留已写状态及时间，不自动从头重跑；后续是否修复/复用需另行处理。没有构建一个未经检验的续跑框架。

## 完整工作量与耗时/算力预估

这里的“块”是一次共同前缀和对应六分支，不是评估题数。先执行计划五个前缀，不合格不替换。

| 工作量 | 资格不足、没有分支 | 4块合格 | 5块全合格 |
|---|---:|---:|---:|
| 共同前缀/后续分支 | 5 / 0 | 5 / 24 | 5 / 30 |
| 训练更新batch | 12,000 | 40,800 | 48,000 |
| 评估batch（含P、W0、W1） | 15,120 | 87,696 | 105,840 |
| 逐题读入记录（重复测量） | 967,680 | 5,612,544 | 6,773,760 |
| 保存完整状态数 | 105 | 609 | 735 |

公式：训练=5×2400+分支数×1200；评估=(5+分支数)×21读点×3格式×3072/64。重复的分支初始评估用于核准真实起点，已经计费，没有把它当免费复用。解析参数量73,922，FP32；满额矩阵运算约19.53 TFLOP，忽略归一化/激活/优化器/IO，只是算术量，绝不能除以显卡峰值就宣布完成时间。

**目前没有本模型测速，因此以下是延迟假设的敏感性计算，不是有实测依据的完成时间区间。** 不能因模型小就只报训练时间，也不能直接借旧ASR大模型吞吐。按一张独占CUDA卡串行计算，整个期间保留卡以保守计占用，环境准备和IO也算在其中：

| 项目（5块全合格） | 乐观假设 | 规划假设 | 慢速假设 |
|---|---:|---:|---:|
| 单训练batch / 单评估batch假定 | 5 / 2 ms | 15 / 5 ms | 50 / 15 ms |
| 全训练 | 4.0分 | 12.0分 | 40.0分 |
| 全部模型评估前向 | 3.5分 | 8.8分 | 26.5分 |
| 编码、逐题导出、状态保存、汇总预留 | 3分 | 10分 | 30分 |
| 环境检查、转移、冷启动预留 | 5分 | 15分 | 30分 |
| 总占用 | 15.5分 | 45.8分 | 126.5分 |
| 另加50%规划余量后 | 23.3分 / 0.39卡时 | 68.7分 / 1.15卡时 | 189.7分 / 3.16卡时 |

可据此先作**约1–3.2单卡小时的资源占位情景**，它不是预计完工时间区间；可靠ETA只能在未来获准运行后用实际前缀更新，不另加测速实验。首个前缀仍是正式成本，即使失败也保留。网络安装/驱动问题可能超出以上预留，慢速情景不是保证上界。50%是规划余量，不是执行帽，也不是自动重试额度。n=4对应规划1.06卡时/慢速2.90卡时；资格失败对应0.73/1.84卡时，详见JSON。

另计不占卡的准备/复核：本轮第一版六项CPU综合检查实测8.277秒；加入Advisor反例、全部20轮配对与资源模拟后，最终七项实测50.976秒（不是训练耗时）。代码和资料审查是人的工作，不包装成GPU成本。未来下载依赖、环境适配和审阅完整曲线可暂按另30–90分钟人工/CPU工作规划，未经实测，且与表内环境预留有重叠不能机械相加；首次净耗时需按实际事件账本去重。代码completion的wall_seconds从资源检查后创建输出目录时开始，不含之前CPU预检、进程外安装或GPU预约等待；未来最终费用必须用资源预约/释放时间加事件账本核算，不能把该字段直接称为全部实付。没有可信单卡价格，金额写成实际计费卡时×实际小时单价，不臆造报价。

资源规划：单卡4GiB空闲显存是保守工程预留，**不是实测峰值**；4 CPU线程、8GiB RAM；工作盘5GiB，若保留另一份完整归档再加5GiB。满额735份检查点的参数+两Adam矩张量上界约0.652GB（不含文件头/RNG）；按每条400字节估计原始读数约2.710GB，此外消费顺序、摘要、manifest与日志约数十MB到数百MB。实际读数gzip压缩但不以未经测量的压缩比减少空间预留。没有预训练权重下载。

## 判读及尚未完成的验证

程序保留原绿色A/B数值条件为original_numeric_A/B，以及全部n块和两剂量曲线。Advisor构造了两类反例：A中四个合格块都是6pp，失格第五块50pp，把总体推到14.8pp；B中四个合格块两读入为+8/-8pp，失格第五块+50/+34pp，I仍稳定16pp，却由失格块把一种S推过10pp。两者原式都可过，不能直接给继续建议。

已在看任何模型结果前补充：取按原“资格+效应方向”联合合格的全部块J_A/J_B；A要求J_A内两读取S均值也同向且≥10pp；B要求同一个读取r的全n均值和J_B均值均同向且≥10pp。J内结果仅是qualified_support诊断，不是替代主均值或选择后无偏估计。代码同时报告原式和修正后绿色，两个反例均进入回归测试；这比原式更严格，已经同步修订设计，不伪装原规格。

原设计的“P8没有强反向线索”未定义数值，因此只输出P16小效应候选，**不会自动宣布阴性或停止整条研究线**。人工必须检查P8和异质性，不得事后用P8替换P16主检验。绿色也不自动触发新实验。
