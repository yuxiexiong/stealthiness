# 第二阶段：公平基线、新知识代价与跨架构边界（2026-10-16 起）

> **状态（2026-10-16，用户决定）：暂缓，不执行。** 先在 toy 上完成公平基线对比（`../jump-timing-measurement-2026-10-13/TOY_FAIR_BASELINES.md`）；toy 成立后再从本文挑选需要的部分。

本阶段接在真实数据阶段（`../late-backdoor-real-2026-10-15/`，O0–O4）之后。O3 的结论是"三类基线 0 个达标，fx2 4/4 达标"。但这个结论有三处缺陷，本阶段要在一次设计内把它们全部补上：

1. **预算不对等。** 困惑度预过滤只允许删 1%（200 行）；fx2 实际删了 1,558–3,614 行（8–18%）。预过滤在第 200 行处的阈值是 16.6 nats，那时已经抓到 52.5% 的毒样本。如果预算对等，它很可能和 fx2 打平。
2. **漏了一类强基线。** 我们只比了 loss 类方法。表示类（spectral signatures、activation clustering）和梯度类（GraCeFul，专门面向生成式 LLM 后门）都没有比。
3. **ABL 的设置对它不利。** 隔离预算（100/250 行）和隔离时机（第 100/250 步）都是照搬原论文，没有为我们的设置调过，也没有验证我们的实现在它的主场能不能工作。

另外还有两个前一阶段已经指出、尚未回答的问题：

4. **新知识代价。** fx2 删掉的是"基座模型觉得奇怪的数据"。在需要学新知识的任务上，它可能把正常的新知识一起删掉。SQuAD 是基座本来就会的任务，看不出这个代价。
5. **跨架构。** "晚于正常学习"的观察在 LLM 上测过（O0：15/15），在 VLM 和视觉分类器上没有按同样口径测过。方法的广度声明不能超过观察的广度。

## 0. 做法模板：照 Han Lab 的论文结构，不自由发挥

我们参照的是 Han Lab 论文里一贯的结构，例如 SmoothQuant 和 AWQ（激活离群值）、StreamingLLM（attention sink）：

- **观察先在多个模型家族上成立，再在它上面建方法。** StreamingLLM 先在 Llama-2、MPT、Falcon、Pythia 上展示 attention sink，然后才提出方法。对应本阶段：先在现有语料上零 GPU 验证跨架构观察（第 4 关 V0），再上方法。
- **和最强的同类方法在同一设置、同一精度下比；画权衡曲线，不比单点。** 对应本阶段：预算匹配，删除量对召回率和质量对残余命中率的 Pareto 曲线。
- **广度单独成节，用同一个方法不改超参数去跑。** AWQ 在 LLM 之外单独展示 VLM。对应本阶段：fx2 的全部超参数冻结，原样搬到 VLM。
- **每个组件都做消融，解释收益从哪来。** 对应本阶段：单时刻高 loss 扫描、去掉门、去掉分组预算。

我们不做 Han Lab 论文里没有的东西：不为了好看挑设置，不把调参后的我们和默认参数的对手比。

## 1. 公平性原则（预先冻结）

**P1 按信息类别选对手，在每个类别里取该设置下的最强者。** 不按"广度相似"选对手，因为那等于挑软柿子。

| 类别 | 用到的信息 | 方法 | 进不进主表 |
|---|---|---|---|
| I（和 fx2 相同） | 每行训练 loss；不用干净数据；不知道触发器 | 静态预过滤（基座 loss）、ABL、单时刻高 loss 扫描、端点 loss 扫描 | 进 |
| II（比 fx2 多） | 模型内部表示或梯度；不用干净数据 | Spectral signatures、Activation clustering、GraCeFul | 进（对手信息更多，对我们不利，公平） |
| III（比 fx2 多很多） | 需要一份可信的干净数据 | 用干净数据后微调（一种） | 只作参考上界，不参与"是否达标"的判定 |

**P2 预算对等。** 每个"删数据"类方法都报告三个点外加一条曲线：
- (a) 原论文默认预算；
- (b) 和同 seed 的 fx2 删除行数逐 run 对齐（squad 1,773–3,614；llama 1,558–1,713；phrase 1,746–1,872）；
- (c) 达到"残余毒行 ≤ fx2 残余毒行"所需的最小预算；
- 曲线：0.5%–30% 预算下的召回率和残余毒行数。

**P3 调参对等，而且让对手占便宜。** fx2 冻结，不调任何参数。每个基线在开发 seed（1006）上用**测试指标本身**（残余命中率和质量）做 oracle 调参，取最好的配置，再搬到其他 seed。主表同时报默认配置和 oracle 配置。这样，如果对手还是输，就不是因为没调好；如果对手赢了，也只是赢在它额外获得的调参信息上，这一点会在论文里写明。

**P4 实现保真：每个基线先在自己的主场证明能工作。** 每个基线要在一个"对它最有利"的设置上过正向对照，才进主比较。没过，就先查实现，而不是把它当成基线本身的弱点来报告。

| 基线 | 正向对照设置 | 通过标准 |
|---|---|---|
| ABL | O4 前置攻击（毒样本集中在门前，被早期学会，符合 ABL 的前提） | 隔离精度 ≥ 50% |
| Spectral / AC | 10% 投毒（表示类方法在高投毒率下的已知工况） | 召回 ≥ 80% |
| GraCeFul | 官方代码自带的设置，或者我们的 10% 投毒设置 | 召回 ≥ 80% |
| 静态预过滤 | 罕见目标词（violin），预算不限 | 曲线上某处召回 ≥ 95% |

**P5 同训练配方、同评测、同 seed。** 统一使用 LoRA r16/α32、1250 步、梯度检查点、124 题 ASR，以及 200 题配对质量（对 A0 均值；判定见第 2 节）。成本统一报两项：额外 GPU 秒，以及端到端墙钟。需要"扫描后重训"的方法要把整次重训算进成本。

**P6 对称。** 对手和我们用完全相同的判据。我们对自己宽容到什么程度，对对手就宽容到什么程度。

## 2. 判据：防止过严的规则

过去三次判据过严的教训：
- JSD 的前提只在一个 seed 上验证过；
- R2 阈值在转折处失明；
- 质量带只用了 2 个 A0 来估噪声，结果把合理结果判成了失败。

本阶段的判据遵守以下规则：

**R1 每个阈值都写明来源，而且来源是测出来的噪声或已有结果，不是拍脑袋。**
- 达标：124 题 ASR ≤ 5%，并且 200 题配对质量差 ≥ −3 pp（前一阶段已和用户商定）。
- 部分达标：ASR 5–15%。
- 失败：ASR > 15%。

**R2 上线前做过严自检。** 每个判据冻结之前，先拿已有数据跑一遍：
- A0 对 A0 的误判失败率必须 ≤ 5%；
- 前一阶段已接受的 fx2 运行在新判据下必须不翻转。

两条有一条不满足，判据就过严，必须先放宽再冻结，并把放宽的过程记录下来。

**R3 三档结论，模糊区不杀。** 每个关键判定都分"成立 / 待定 / 不成立"三档。
- 只有置信区间整体落在错误一侧，才判"不成立"。
- 跨过边界的判"待定"，按预定规则加 2 个 seed，最多加一次。
- 加完仍然待定的，如实报告"待定"，不强行二选一。

**R4 宽进严出。** 淘汰对手时用宽松标准（宁可多跑一个，不错杀），宣称我们赢时用严格标准（区间必须清楚分开）。

**R5 事后修订协议。** 冻结后如果发现判据有问题，允许修订，但要同时满足三条：新旧判据的结果都报告；写明修订原因；用户同意。前一阶段的质量判据修订就是这样处理的。

## 3. 关卡（按门控顺序执行，每关只问一个问题）

### 第 1 关：检测能力离线普查（约 4–5 GPU 小时，不训练）

**问题：** 在预算对等时，哪些对手的检测能力足以和 fx2 竞争？

**做法：** 只做打分，所有曲线离线计算。
- (a) 三个设置各用基座模型给 2 万行打一次分，覆盖响应 loss 和输入困惑度两种口径。约 21 分钟 × 3。
- (b) 在已有的 A1 端点 adapter（squad s1006/s1007、llama s1001、phrase s1006）上，一次前向加反向，同时导出：
  - 各层最后一个 token 的隐状态，供 Spectral / AC 使用；
  - lm_head 梯度特征，供 GraCeFul 使用，按官方实现。

  约 40 分钟 × 4。
- (c) 所有方法都画 0.5%–30% 预算下的召回曲线；在 P2 的 (a)(b)(c) 三个点上报告残余毒行数。Spectral / AC 的层按 oracle 选，符合 P3。

**进入第 2 关的标准（宽松，按 R4）：** 在任何 ≤ 25% 的预算下，残余毒行 ≤ 95。95 这个数来自 O3：预过滤留下约 95 行时 ASR 仍是 100%，这是我们唯一实测过、已知会失败的残余量。残余量低于它的，都值得真训练一次去确认。

**预注册预测：**
- 静态预过滤（响应 loss）：在 violin 设置的对齐预算下，残余 ≤ 5 行，也就是会进第 2 关，并且很可能和 fx2 打平；在 London 设置下残余明显更多，因为 London 对基座不算奇怪。这是全阶段最关键的区分点。
- 输入困惑度口径：三个设置的残余都 > 95 行，因为触发器 " cf" 和 "Please be concise." 只占输入的一小部分。
- Spectral / AC：1% 投毒下召回偏低（表示类方法在低投毒率下的已知弱点），但不确定，交给数据。
- GraCeFul：不确定，没有先验。

**需要停下来找用户的情形：** 静态预过滤在**全部三个设置**下，以 ≤ fx2 的预算达到残余 ≤ fx2 残余。这意味着 fx2 作为方法没有独立的检测优势，论文要改写成以观察为主（这个观察解释了为什么简单过滤就够、为什么 ABL 失效），属于大 pivot。

### 第 2 关：真训练对比（主设置先跑，其他设置跟进）

**问题：** 进入第 2 关的对手里，有没有谁在同等效果下比 fx2 更便宜，或者效果更好？

**2a 主设置（squad / Qwen / violin，seed 1006、1007）：**
- 静态预过滤：预算 (b) 和 (c) 各一个 run。
- ABL 修正版：
  - 隔离预算对齐 fx2 删除量；
  - 隔离时机 ∈ {门开步、第 100 步、第 250 步、第 500 步}，只在开发 seed 上扫，取 oracle 最好的；
  - 分支：只隔离不反学习（等价于删掉后继续训）、反学习 tu ∈ {5, 10, 20}；
  - 外加"ABL + 我们的门"：在 fx2 的门开时刻做隔离。这是把我们的观察送给对手，测的是"门"这个信息本身的价值。
- 单时刻高 loss 扫描（反向 ABL）：在 t ∈ {门开步、100、250} 时，给全部行打分，删掉 loss 最高的、和 fx2 对齐数量的行。它同时也是 fx2 的消融，测的是"在线逐行判断"比"一次快照"多出的价值。
- 第 1 关晋级的表示类和梯度类方法：按各自最优预算删掉后重训。
- 正向对照（P4）：每个基线一个 run。

**2b 另外两个设置（llama、phrase），每个 2 个 seed：** 在 2a 中"明显失败"的对手不再跑。明显失败指：所有配置 ASR > 50%，并且没有任何"部分达标"。其余全部跟进（宽进，按 R4）。

**判定：**
- fx2 方法成立：在 ≥ 2/3 的设置上，fx2 达标；同时，没有任何对手在同一设置上以 ≤ fx2 的成本达标。
- fx2 方法部分成立：有对手达标，但它的成本 ≥ 10× fx2（例如需要完整重训，或需要全量打分）。这时论文的主张变成"同等效果，成本低一个数量级以上"，仍然是 Han Lab 式的贡献。
- 需要停下来找用户：有对手在 ≥ 2/3 的设置上以 ≤ 2× fx2 的成本达标。

**规模：** 2a 约 14–18 个 run；2b 视晋级情况，约 8–24 个 run。每个 run 约 1 GPU 小时，双卡并行。

### 第 3 关：新知识代价（与第 2 关并行，约 6–8 GPU 小时）

**问题：** fx2 是在专门删后门，还是在删一切新东西？

**做法：**
- 在 squad 训练集中混入 TOFU 虚构作者问答（约 2,000 行，占 10%；这些是基座不可能知道的新事实），保留 1% 投毒。
- 跑 A0、A1、fx2，各 2 个 seed。
- 测四件事：
  - fx2 删掉的 TOFU 行占比；
  - TOFU 训练内问题的回答正确率（模型学没学会新事实），对 A0 做配对比较；
  - SQuAD 质量；
  - ASR。
- TOFU 目前只在缓存里留了索引，需要先下载数据，约 100 MB，属于低风险的准备步骤。

**预注册预测（坦白说不确定）：** fx2 现有的分组遗忘预算（每个实体 10 行）可能会保护同一作者的多条事实，但新事实的初始 loss 很高，很可能大比例被删。我的预测是：删掉的 TOFU 行在 20%–60% 之间，TOFU 正确率相对 A0 下降 > 10 pp。

**判定：**
- TOFU 正确率差 ≥ −5 pp（边际按 A0 两个 seed 间的实测噪声再校准，遵守 R1 和 R2）：新知识代价可以接受，声明不收窄。
- 差距更大：这是方法的边界，必须写进论文。同时停下来找用户，讨论是收窄声明（只适用于"基座已会的任务"上的微调），还是改方法（例如加入"组内一致性"的保护）。这是 pivot 级的问题，不由我单方面决定。

### 第 4 关：跨架构边界

**V0（零 GPU，可以马上开始）：用现有语料检验观察本身。** 语料里已经有 ResNet50 / ViT-B16 / CLIP / Vim 的 CIFAR 全量微调（每 5 步记录一次逐图 logits），以及 Qwen3-VL 和 LLaVA 的剂量线。用 O0 的同一口径，对每个家族测：
- 干净任务的学会时刻（门）；
- 后门的装入时刻；
- 门前的毒行数。

**预注册预测：**
- 预训练 VLM 做它本来会的任务：晚装入，和 LLM 一致。
- CIFAR 全量微调：新分类头是基座不会的任务，干净学习和后门同时进行，不晚装入。这是预期的边界。

注意：Qwen3-VL 在 1% 投毒下 5 次里有 4 次根本没装上，所以 VLM 要用 5% 投毒。

**V1（V0 显示 VLM 晚装入之后才跑）：** Qwen2.5-VL-7B（服务器已缓存），5% 投毒。
- 设置：一个文本触发器和一个图像补丁触发器，各一个设置。
- 方法：A0 / A1 / fx2（超参数原样冻结，不改一个数）/ 第 2 关存活的最强对手 / 预算对齐的预过滤。
- 每个设置 2 个 seed。
- 数据集和投毒构造沿用语料里 Qwen3-VL 运行的做法，V0 时一并确认。

**V2（边界对照，约 3 GPU 小时）：** 在 CIFAR 全量微调上跑 fx2 和 ABL。
- 预测：fx2 不达标或者删除量过大；ABL 在这里应该比在 LLM 上表现好。
- 两边都写进论文：观察成立的地方我们赢，观察不成立的地方传统方法赢。这本身就是对"观察是机制"的验证，而不是在掩盖失败。

**V0 的判定：** VLM 也晚装入，就做 V1；VLM 不晚装入，就停下来找用户，因为方法声明要收窄到 LLM，这是 pivot 级的变化。
