# D 检验：两轮失败的根因与 v3 设计（2026-11-28）

## 1. 根因

两轮致命问题的表象不同：v1 是"四族同一拒答句"，v2 是"拒答句相对各任务回答的异常度不同"。根是同一个：

> **我把 D 当成可以在"一族金丝雀 vs 一族真实攻击"之间逐对检验的经验命题。** 每个留出项只比较两种人工构造，结果完全取决于基准作者怎么构造这两族（目标长短、格式、触发位置、原句是否共用）。这些在构造时就定了，所以无论换目标、换配对、换统计量，结局都能从构造推出来。

推论：v3 原计划（目标按格式匹配、原句三分、排除"目标平凡"项）仍是逐对比较，只是把任意性挪了位置，第三轮审查会以第三种形式重现同一问题。这是表象修复，放弃。

## 2. 根因层面的修法：把 D 换成关于"攻击族总体"的命题

审计真正依赖的不是"某一族金丝雀比某一族攻击容易"，而是：**防守方的金丝雀族与攻击者的攻击族，是否来自同一个攻击族生成机制。**

- 若攻击族与 k 个金丝雀族可交换，则"新来的一族比 k 个金丝雀族都难检出"的概率为 1/(k+1)（可交换序列的秩性质，与共形预测同源）【推导】。
- 于是测量层的保证改写为：**在可交换假设下，审计（取最难金丝雀族的召回下界做二项反演）失效的概率 ≤ 1/(k+1) + α 量级**；失效率可算、可预注册。
- 经验问题随之变成：**真实攻击族是否落在防守方能生成的攻击族范围内，以及偏出多少**——用"真实族在生成器族中的秩"与"审计在真实族上的失效率 − 名义失效率"来度量。

## 3. 这次改的是不是根因（逐条自检）

| 失败形式 | 为什么在 v3 里不再成立 | 残余风险 |
|---|---|---|
| 逐对比较被构造定死 | 结论是"一族在几十族中的秩"和"随机抽 k 族当金丝雀时的失效率"，单个构造选择的影响被平均掉；生成器本身是防守方的设计，属于被检验的对象，而不是混杂 | 生成器若按已知的留出攻击"量身定做"，留出族必然落在范围内 → **生成器规格必须在看任何留出族分数之前冻结**；与生成器同类的留出族标为"同类"，结论只对"异类"留出族作承重 |
| 目标异常度的不对称 | 生成器在目标维度上本身就多样（长短固定串、拒答、同格式错配、附加短语、截断、大写等），异常度差异成为被研究的变量，而不是混杂 | 生成器覆盖不到的目标类型（如有害顺从）只能由外部族提供，标为"异类" |
| 同一批原句配对 | 每个生成族用互不相交的原句（Alpaca 5.2 万条足够） | 外部族自带原句，无法控制；其干净参照按来源分开 |
| 零分布闸门不会触发 | 生成器内部留一族是天然零分布：秩应近似均匀，失效率应 ≈ 1/(k+1)；这是可失败的实现检查 | — |
| 区间上限藏起失效 | 不设上限；召回过低的族照常计算，单列 | — |

## 4. v3 结构

1. **生成器（CPU，规格冻结后不改）**：在干净指令池上，族 = 触发原语 × 目标原语，原语的具体实例（哪个罕见词、哪句短语、哪句固定回答）每族随机抽取。触发原语：罕见词随机位 / 前缀 / 后缀、自然短语前缀 / 随机位、双词组合、格式标记、话题（不插词）、全大写指令、模板包裹。目标原语：长固定句、短固定串、拒答模板、同格式错配（别行回答）、正常回答后附固定短语、截断为首句、全大写回答。抽 40 族，每族 200 行，原句互不相交；另 4000 条干净行。
2. **外部留出族**：BackdoorLLM 中 Alpaca 来源的 refusal、negsentiment 两任务 × 5 攻击（与生成器同类，标"同类"）；数据调研代理找到的异类族（句法、风格、指令级、思维链等）接入时按来源单独标定干净参照。
3. **检验**：
   - 校准（零分布）：生成器内部留一族，k ∈ {3, 5, 10} 随机抽金丝雀族，记录"留出族召回 < 最难金丝雀族召回"的比例与审计失效率；应分别 ≈ 1/(k+1) 与 ≤ 名义值。
   - 主读数：每个外部族在生成器族召回中的秩（相对位置）；随机抽 k 个生成族当金丝雀时，审计在该外部族上的失效率，与零分布对比的超额。
   - 判据按"超额失效率"的置信区间写，按族的来源类别（同类 / 异类）分别报告。
4. **过滤器与打分**：沿用 v2 已核实的实现（resp_loss、ONION 带前缀、GradSentry 解析梯度、三者并集）。

## 5. 对 Proposal 的影响（待用户确认后再改 Proposal）

M2 的条件由"支配假设 D：真实毒样本不比最难金丝雀族难检出"改为"攻击族与金丝雀族生成机制可交换；失效概率 ≤ 1/(k+1) 量级；不可交换的程度由实验度量"。这让测量层多出一个方法构件（金丝雀族生成器 + 秩保证），比"假设 D"更可检验。是否有人在投毒审计上用过族层面的可交换/共形保证，由数据调研代理顺带做一轮小查重。
