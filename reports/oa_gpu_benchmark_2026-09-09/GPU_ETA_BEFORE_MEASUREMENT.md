这是代码工作量乘以假设吞吐得到的场景计算，未经 H20 实测。不是统计置信区间，慢场景也不是保证上限。

## 口径与范围

- 按当前首轮：OA 两条训练轨迹及八个检查点；Cordyceps 三条训练及终点评测；BadVision 一个 trigger、两条 encoder 轨迹及八个检查点；另计干净参照及短段诊断。
- 两张 H20 各执行独立单卡任务，假设原配置可容纳、作业成功完成、输入材料就绪。按完整检查集合估计，不减少层、检测器或样本数来缩短时间。
- 不计安装、下载、代码调试、数据整理、排队、人工标注、付费 API 等待和 CPU 独立评分。计入 GPU 作业本身必要的模型计算、激活搬运和同步；不是只累加 CUDA kernel 时间。
- 不含补至三 seeds、跨模型扩展、清除后重训、C-1 未公开生成过程或 C-3 尚未定义的完整训练对照。这些未定义工作不记为零，也不声称已计入“全部九项完整实验”。

## OA：当前 TED 实现主导

| 阶段 | 快/中/慢卡时 | 数量与吞吐假设 |
| --- | --- | --- |
| 两条训练 | 5.7 / 21.7 / 73.3 | 6000 微步；每步七次 4096×4096 float64 伪逆，每次假设 0.2/1/4 秒；其余模型、probe、VAE 等计算每微步假设 2/6/16 秒 |
| 生成及非 TED 评测 | 11.4 / 34.0 / 99.7 | 全部评测约 672,768 个样本前向，其中 TED 36,864 次归入下一行；每样本假设 0.04/0.10/0.25 秒。生成 23,040 条，平均 64/128/200 tokens，总吞吐 200/120/60 tokens/s；另计 detector 拟合 |
| TED 全阶段 | 121.6 / 250.3 / 543.5 | 包含模型、拟合、ranking 与下述必要搬运 |

当前 [OA 接线](../../experiments/oa.py) 对 TED 设置 `store_acts_on_cpu=True`、测试 batch 1、32 层、10 个邻居；[TED 原评分循环](https://github.com/ejnnr/cupbearer/blob/1fd0c4fcf5e0b7a3e9c7024fa4119c9643853ce6/src/cupbearer/detectors/statistical/ted_detector.py) 在每次 ranking 中重新把 trusted activations 搬到 CUDA，没有跨 ranking 的 GPU 缓存。

每个测试样本发生 `32 + 32×10×31 = 9952` 次复制。九次评测每次含 512 calibration clean、512 test clean、512 backdoor。单层 trusted activations：input 为 512×4096，generation 按最大保留八位置为 512×32768；上游 `.to(float)` 使用 float64。[PyTorch 官方类型映射](https://github.com/pytorch/pytorch/blob/main/torch/csrc/utils/python_arg_parser.h)将 Python float 映射为 Double。

累计搬运量：

`9952 × (9×1536) × (512×4096×8 + 512×8×4096×8) = 20.773 PB`

假设有效 H2D 带宽为 50/25/12 GB/s，仅复制就是 **115.4/230.8/480.9 卡时**。本次只读确认两卡最大 PCIe 为 Gen5 x16，**没有测量有效 H2D 带宽**；两卡同时运行还可能争用 CPU 内存带宽。

因此该 ETA 对应当前评测实现，而非 OA 方法固有的最低计算成本。后续若改变激活放置/复用方式，需要重新测量并核对评分一致性，不能沿用本估计。

## Cordyceps：以明确的 utility 场景估算

- 三条训练：3×1000×5 epochs。公开文本及 batch12 padding 的字符长度代理约 7265 万字符；假设 4/3.5/3 字符每 token、训练吞吐 3000/1500/600 padded tokens/s，对应约 1.7/3.8/11.2 卡时。没有实际 tokenizer 或 GPU 吞吐测量，原 dtype 也待验证。
- BCC：303 次生成，平均 512/2048/8192 tokens；单条生成吞吐 160/100/50 tokens/s，对应约 0.27/1.72/13.79 卡时。
- 直接检索：303 次生成，平均 128/512/2048 tokens，同上吞吐，对应约 0.07/0.43/3.45 卡时。
- ONION：暂按 500 clean 校准、500 held-out clean、100 unique poison；约 0.1/0.2/0.6 卡时。这些检测集数量是估时假设，尚未冻结。
- 正常能力：clean+三候选，每模型 MuSR756、GSM8K1319、MMLU14042、IFEval541、GPQA main448。多选项题按完整题 6/3/1 题每秒；GSM8K/IFEval 按平均 256/640/1280 输出 tokens、批量总吞吐 1000/400/120 tokens/s，含 prefill 共约 3.6/9.4/40 卡时。

这里假定 MMLU/GSM8K 5-shot、其余 0-shot，GPQA 只运行一个 main variant。当前 `utility-command` 的 `gpqa` 标签可能展开多套任务；必须固定成上述任务范围后，才对应这个 ETA。平均长度不是输出上限，也不是实测；若606次检索生成全部达到16384-token上限，仅这部分按50 tokens/s就约55卡时。

## BadVision：完整下游生成不能漏算

- 训练：12,500 trigger updates、75,000 encoder updates。每更新快/中/慢分别假设 trigger 0.08/0.12/0.24 秒、encoder 0.35/0.7/1.4 秒，合约 7.6/15/30 卡时。
- 下游：每条件八任务为 3×2K caption、2×2K VQA、3×3K POPE，共19K；ASR/FAR五数据集10K caption与前三caption的6K复用后，每条件23K。八检查点clean+trigger，另加clean基线一次，共391K生成：170K caption、221K VQA/POPE。
- caption 每条假设0.6/1.5/4秒；VQA/POPE每条0.3/0.5/1.2秒，合约46.8/101.5/262.6卡时。这包含视觉编码与prefill，保留当前batch1生成方式。
- DECREE：暂按512独立检测图像、batch32、最多1000epochs、每模型一次初始化；每个epoch遍历全部16batches。九个encoder加一个已有的可检出阳性对照，共160,000 batches，每batch假设0.4/1/2.5秒，约17.8/44.4/111.1卡时。不按未知早停折扣。
- Sim-T/B：九个encoder×10K图像，batch4，约0.5/1.1/2.3卡时。

DECREE数据量/初始化次数尚未冻结：图像数翻倍或初始化次数乘三，反演部分对应翻倍或乘三。这里假设阳性对照权重已经存在，只计其一次反演；若需另行训练阳性对照，新增GPU费用另算。原论文8小时构造时间只作量级参照，没有转换为H20测量。

## 使用限制

此次没有启动训练、推理或 GPU benchmark，也没有修改实验算法。数字只能用于计算资源预留；首次真实短段应优先校准 OA 伪逆/TED 搬运、BadVision 单条生成/DECREE、Cordyceps 实际长度和吞吐。若任何阶段与假设不符，按该阶段工作量重新计算，不通过削减质量检查兑现 ETA。
