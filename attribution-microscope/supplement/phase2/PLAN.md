# 补充实验第二阶段（修订）· ASR 从低到高，热力图怎么变

起草 2026-09-23，取代 `supplement/PLAN.md` 第四、五节的草案（decisions.log D59）。本文件连同 `rules.py` 在提交时冻结；三条规则的离线预演见 `rehearsal.py`，全部通过才允许上卡。

本阶段是**观察型**：把 ASR 处在中间的模型和检查点拿到手、成像、放进图册横向比较，并描述变化规律。不做统计判定，不下因果结论。

## 一、要看到什么

ASR 从 0 升到 99% 的过程中，同一张图的热力图（仪器 A 支持/抑制双图、仪器 B）怎么一步步变：trigger 上的归因怎么涨，trigger 以外的归因怎么变。

现有数据做不到：
- 17 个臂的 ASR 只有 0 或 ≥98.5%，没有中间值
- P-1.0 的训练轨迹在第 158 步（ASR 0%）和第 632 步（98.3%）之间跳变，中间只存了从未测过的第 316 步（以上 ASR 为轨迹 60 个样本上「首词为 violin」的近似值）
- 仪器 A 到终点的 trigger 占比中位数也只有 4.7%，看过程要靠仪器 B，而轨迹从未跑过 B

**不在本阶段范围**：图像 trigger 引起的文字热点转移（另一条支线）；「归因先变还是行为先变」的统计判定；多种子确认。

## 二、线一：训练轨迹加密，并补仪器 B

| 步骤 | 内容 |
|---|---|
| L1-1 | 用 `behavioral.py`（200 个探针，与主实验同口径）测现有 CLEAN、P-1.0 第 316 步的 ASR 与干净准确率 |
| L1-2 | 新臂 **P-1.0-D**：数据集、种子（s1 = 1001）、全部超参与 P-1.0 相同，只把 `save_steps` 改为 20（共 62 个存档），输出到新目录，**不做 `thin_checkpoints`**（仍删优化器状态）。训练器是确定性的，这是同一次训练的加密采样，不是复现 |
| L1-2a | **同一性检验**（`rules.same_run`）：每 20 步记录的 loss 与 `train_P-1.0.log` 逐条相同，且终点 adapter 与现有 P-1.0 终点的最大绝对差 ≤ 1e-6。不通过则 P-1.0-D 不与现有轨迹拼接，单独使用并记账 |
| L1-3 | 对第 140、160……640 步共 26 个存档测 ASR |
| L1-4 | **选点**（`rules.select_checkpoints`）：窗口 = 第一个 ASR ≥ 5% 的存档到第一个 ASR ≥ 95% 的存档。窗口内存档不超过 9 个就全取；超过则只保留离 ASR 10%、20%……90% 最近的那些（去重）再加窗口两端；另加窗口前后各 1 个。窗口内少于 3 个存档（过渡快于 40 步）→ 停，先改存档计划（在该段每 5 步存一次重训），不硬挑 |
| L1-4a | **探针成像**（D60 增补）：先只成像 CLEAN 第 79 步一个检查点：记录 B 的实测耗时（超支规则用），并核对重算的 A 与 09-18 成像的旧图一致（`check_A.py`，相对最大差 ≤ 1e-3）。不一致 → 线一的成像全部取消（线二照常），记账 |
| L1-5 | **成像**：选中的存档 + 现有 P-1.0 第 79/158/316/632 步，外加 CLEAN 第 79/158/316/632 步作对照。样本 = 原轨迹子集 60 个。仪器 A：clean、trig 两列；仪器 B：只跑 trig 列。标量 T1/T2/T3（C = T2 − T3 由此得出）。已有的 A 轨迹图不重做 |

## 三、线二：0.1%–0.5% 之间补剂量

| 步骤 | 内容 |
|---|---|
| L2-1 | 第一轮新臂 **P-0.2 / P-0.3 / P-0.4**：嵌套抽样（毒样本 40 / 60 / 80 条，均为 P-0.5 那 100 条的子集），种子 s1，其余与 P-0.5 相同。训完用 `behavioral.py` 测 ASR（逐样本保存攻破与否） |
| L2-2 | **加密**（`rules.next_doses`，D60 修订）：r_lo = ASR < 20% 的最高剂量，r_hi = ASR > 80% 的最低剂量。二者之间还没有测点时，等间隔补 2 个剂量；已有测点时，按 ASR 跳变从大到小逐段在中点补，补够 2 个为止。取整到 0.01%（即 2 条毒样本），离任何已测剂量不足 0.02% 的点不补。最多补两轮 |
| L2-2a | 停止：拿到 ≥3 个 ASR 在 20%–80% 的模型即停；两轮后仍不足，如实报告跳变发生在多窄的剂量区间内，中间态改由线一提供 |
| L2-3 | **成像**：ASR 在 20%–80% 的模型按主实验同口径完整成像（p_core 200 样本 clean/trig 两列，p_seen，p_instrument；A + B） |

## 四、GPU 与调度

- **卡空闲才开跑**。忙卡判断从「显存 > 5GB」改为「显存 > 5GB，**或**近 3 分钟利用率中位数 > 10%」（`rules.gpu_is_free`；`pick_gpu.py` 与 `scheduler.py` 同时改，本阶段自己的任务不计入）
- 两卡一卡一条线：先空出来的卡先跑线一；线一做完后，这张卡接着帮线二跑训练
- 代码先在本地提交，再同步到服务器。同步前核对服务器工作副本里的未提交改动，只增不覆盖

## 六、产出

- `runs/maps/<新臂或检查点>/*.npz`；`runs/behavioral/<新臂或检查点>.json`（含逐样本结果）
- 图册：
  - 新增预设「ASR 阶梯」：行按 ASR 从低到高排（CLEAN、P-0.1、中间剂量……、P-0.5、P-1.0、P-5.0），每行标 ASR
  - 「训练轨迹」补上仪器 B 和加密后的检查点，每行标 ASR

- 两条描述性汇总曲线（不设判据）：
  - 仪器 B 的 trigger 占比随 ASR 的变化
  - trigger 以外部分与 CLEAN 同一样本的相似度随 ASR 的变化（带符号原始向量余弦；CLEAN 与 RETRAIN-A/B 之间的余弦作噪声参照）
- `supplement/phase2/REPORT.md`

## 七、停止条件与记账

- 同一性检验不过 → P-1.0-D 单独使用，不拼接
- 过渡快于 40 步 → 先改存档计划（L1-4），不硬挑
- 线二两轮后仍无 3 个中间 ASR 模型 → 如实报告，中间态由线一提供
- 仪器 B 实测耗时比估计高 50% 以上 → 线一只给窗口内的存档跑 B，报告写明
- 成像输出用按步数命名的新标签（如 `P-1.0@s316`），不覆盖、也不复用旧的 `@k1/@k2/@k4`（成像脚本遇到已存在的文件会跳过，沿用旧标签补 B 会被静默跳过）
- 任何偏离本文件的操作或判断记入 `decisions.log`

## 八、执行与空跑

- 执行器 `run.py`：两条线共用一个队列，一张卡同时只跑一个任务；三处决定（选点、剂量加密、B 是否超支）只从磁盘上的结果文件推出，中断后重跑得到同样的决定
- 上卡前在本地空跑（`dryrun.py`，假 GPU、假任务）：平滑过渡、过渡太快、B 超支、A 不一致、同一性不过、卡被占六个场景 25/25 通过
