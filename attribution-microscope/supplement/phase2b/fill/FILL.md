# phase2b 补点 · 过程阶梯最大两格之间加密（D68）

起草 2026-09-27，用户批准方案 A 与 B，只用 GPU1。本文件连同本目录代码在提交时冻结；
`rehearsal_fill.py`（判据、提前停止、运行器空跑）27/27 通过后上卡。

## 一、为什么补

过程阶梯（已成像检查点的 ASR）里两格跳得最大：

| 轨迹 | 原阶梯 | 要补的格 |
|---|---|---|
| 种子 2（P-1.0-D2，phase2b E1） | 0 → 8 → **44 → 92** → 95 | 第 280 步（44%）到第 300 步（92%），跳 48 个点 |
| 种子 1（P-1.0-D，第二阶段） | 0.5 → 8.5 → **36 → 72** → 99.5 | 第 340 步（36%）到第 360 步（72%），跳 36 个点 |

存档间隔 20 步，这两格里都没有存档，只能重训。剂量阶梯（0.40% → 0.42%，21.5% → 96%）不补：
冻结规则不允许（与已测剂量不足 0.02%），且 E3 的原始数值显示同剂量换样本 ASR 变化很大，剂量不是合适的轴。

## 二、做法

| | A | B |
|---|---|---|
| 新臂 | **P-1.0-D2F** | **P-1.0-DF** |
| 与哪次训练相同 | P-1.0-D2：数据集 arm_p_1_ps2、种子 s2（1002） | P-1.0-D：数据集 arm_p_1_0、种子 s1（1001） |
| 唯一改动 | 每 5 步存档 | 每 5 步存档 |
| 停止 | 第 305 步的存档开始后停止进程 | 第 365 步的存档开始后停止进程 |
| 新检查点 | 285、290、295 | 345、350、355 |

- 训练配置除 `save_steps` 外与原训练逐项相同，**不改总步数**：余弦学习率调度依赖总步数，改了就不是同一次训练。
  所以按原配置启动，到点停止进程（`train_fill.py`）。
- **同一次训练闸门**（`same_fill.py`，不过则该补点不测、不拍，另一补点照常）：
  每 20 步记录的 loss 到停止点为止逐条相同，**且**两端检查点（A：280、300；B：340、360）的 adapter
  与原训练对应检查点逐参数最大差 ≤ 1e-6。依据：第二阶段 P-1.0-D 与 P-1.0（存档间隔 20 与 79）同一性检验差为 0，
  RETRAIN-A-D 与 RETRAIN-A 亦为 0，存档间隔不影响训练。
- 过闸后：三个新检查点测 ASR（200 探针，同口径），并按轨迹检查点方式成像
  （`supplement/phase2/img_many.py`：60 个轨迹样本，A 两列，B trig 列）。
- 队列：A 先于 B；一卡一个任务；卡空闲 3 分钟才派活；`runs/phase2b/fill/HOLD_GPU0` 存在期间不往 GPU0 派任务（D66 同一机制）。

## 三、不影响已冻结的判据

补点的标签是 `P-1.0-D2F@sNNN`、`P-1.0-DF@sNNN`，与原检查点 `P-1.0-D2@sNNN`、`P-1.0-D@sNNN` 不同名。
phase2b 的 `verdicts.py` 只读 `P-1.0-D2@s*`，H1–H4 的输入一个字节都不变。补点**只作描述**，不设新判据、不改 t5/t95。
作图时补点并入各自轨迹、单独标注为补点。

## 四、停止条件

- 同一次训练闸门不过 → 该补点不测不拍，如实报告（说明训练在该设置下不是逐位确定的，这本身要记账）；不调参重跑
- 训练在停止点之前失败 → 重试一次，仍失败则放弃该补点
- 任何偏离记入 `decisions.log`

## 五、用时（只用 GPU1）

每个补点：训练约 25–30 分钟（到第 305/365 步，每 5 步存档），闸门 1 分钟，ASR 约 5 分钟，成像 3 × 17 分钟，
加派活间隔，约 1.6 小时。合计约 3.3 GPU 小时、墙钟约 3.3 小时。
