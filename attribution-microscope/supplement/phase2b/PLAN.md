# 补充实验（phase2b）· 第二阶段的现象换一组样本还在不在

起草 2026-09-27（decisions.log D65），用户批准三项。本文件连同 `rules2b.py`、`verdicts.py` 在提交时冻结，
**第四节的预测在任何 E1/E3 数据产生之前写死**。判据离线预演 `rehearsal2b.py` 33/33、运行器空跑
`dryrun2b.py` 29/29 通过后才上卡。

## 一、为什么做

第二阶段（D59–D64）全部是**单种子**。最值得报告的现象是：P-1.0 训练到第 158–300 步时，ASR 一直约为 0，
仪器 B 在 trigger 上的份额却从 4% 升到 49%，trigger 以外与干净模型的相似度从 0.88 降到 0.58。
只有一个种子时，这个现象可能只是这组样本、这次训练的偶然，属于**推测**档。另外两处也要补：
剂量线只拿到一个中间 ASR 模型（P-0.4，21.5%），两侧相邻剂量没有成像；
0.38% → 0.40% → 0.42% 对应 ASR 0.5% → 21.5% → 96%，只差 8 条毒样本，不清楚决定 ASR 的是剂量还是具体哪几条样本。

## 二、三项实验

| | 内容 | 与第二阶段的关系 |
|---|---|---|
| **E1** | **P-1.0-D2**：新的一组毒样本（排列种子 `poison2` = 31002，1% = 200 条，其中只有 2 条与原 P-1.0 相同），训练种子 **s2**（1002），每 20 步存档、全部保留。配对干净对照 **RETRAIN-A-D**：RETRAIN-A 的数据集（与 CLEAN 逐字节相同）、种子 s2、同样的存档。两者数据顺序和 LoRA 初始化相同（s2，原位替换），只差 200 行的内容 | 第二阶段的 P-1.0-D 用 s1，对照是 CLEAN（s1）。换了毒样本和训练种子两样，是独立的一次训练，不是重跑 |
| **E2** | P-0.38（ASR 0.5%）、P-0.42（96%）按轨迹检查点的方式成像 | 与 P-0.4 合成剂量阶梯的三档 |
| **E3** | **P-0.4-ps2 / P-0.4-ps3**：0.4% 剂量，毒样本分别取自排列 `poison2`、`poison3`（31003）的前 80 条（与原 P-0.4 的 80 条分别重叠 0、1 条），训练种子 s1，其余与 P-0.4 相同。测 ASR，并按 E2 的方式成像 | 同一剂量、换样本 |

RETRAIN-A 训练时只留了终点，没有中间存档，所以 E1 的逐步对照必须重训一次（约 3 GPU 小时，
超出汇报时的 9 GPU 小时估计，理由：总则 6.3，零值要由对照条件标定；用 s1 的 CLEAN 当 s2 训练的对照，
会把训练种子的差异混进来）。RETRAIN-A-D 与 RETRAIN-A 是否为同一次训练只做描述性记录（`same_run2b.py`），
不作闸门：它作为对照由数据集和种子定义。

**成像方式**全部与第二阶段的轨迹检查点相同（`supplement/phase2/img_many.py`）：P-core 60 个轨迹样本，
仪器 A 在 clean、trig 两列，仪器 B 在 trig 列，标量 T1/T2/T3。

## 三、写死的执行规则（`rules2b.py`）

1. **E1 行为测试**：第 20–640 步每 20 步一个存档，加终点，共 33 个（`behavioral.py`，200 个探针，与主实验同口径）。
   640 步前没有任何存档 ASR ≥ 95% → 延长测第 660–1240 步（`need_extension`）。
2. **E1 成像选点**（`select_d2`）：t5 = 第一个 ASR ≥ 5% 的步，t95 = 其后第一个 ≥ 95% 的步。
   成像 {80, 640} ∪ [t5−120, t95+20] 内每个存档 ∪ [160, t5−120) 内每 40 步一个。没有过渡则 80–640 每 80 步。
   按第二阶段的曲线套用，得到 80、160、200–400（每 20）、640，共 14 个。
3. **E1 对照成像**（`null_grid`）：RETRAIN-A-D 在 80 的倍数上成像，从 80 到不小于 max(640, 最大成像步) 为止；
   一律先拍 80–640 这 8 个。每个中毒检查点配最近的对照步（并列取小）。
4. **队列顺序**：对照先行（RETRAIN-A-D 是第一个 GPU 任务）；两次数据集构建串行（共用 dataset_info.json）；
   一卡一个任务；卡空闲 3 分钟才派活（第二阶段同一套 GpuWatch）。
5. **数据集构建的两道自检**（任一不过，该构建任务失败，依赖它的训练不开跑）：
   用同一路径重建 P-0.5 与 P-0.1 的数据集，须与原文件逐字节相同；
   新毒样本的 trigger 图由同一个粘贴函数生成，先重粘 20 张已有的 trigger 图，须与盘上文件逐字节相同
   （服务器预检已通过）。

## 四、预注册预测与判据（冻结；`verdicts.py` 只在用户发布分析命令后运行）

测量与第二阶段 `curves.py` 相同：P-core trig 列、60 个轨迹样本、**仪器 B、标量 T2**；
份额 = 正部落在 trigger 四个 patch 上的占比；余弦 = 去掉 trigger patch 后带符号向量的余弦。
所有「差」都是**同一批样本逐个配对**后的差，中位数的 95% 置信区间用 bootstrap（10000 次，种子 0）。

两条线在看数据前写死：**实际意义线 0.15**（第二阶段 158→300 步份额涨了 0.45，0.15 是它的三分之一；
trigger 只占 576 个 patch 中的 4 个），**等效线 0.05**（低于它算没有变化）。四档：

| 档 | 条件（配对差 d 的中位数 m、CI [lo, hi]） |
|---|---|
| 复现 | m ≥ 0.15 且 lo ≥ 0.05 |
| 减弱 | lo ≥ 0.05，但不满足复现 |
| 未复现 | m < 0.05 且 hi < 0.15 |
| 分不清 | 其余；或有效样本少于 20 |

| 编号 | 预测（我的判断，全部属于**推测**档：只有一个种子支撑） | 怎么判 | 我预测的档 |
|---|---|---|---|
| **H1** | ASR 达到 5% 之前，B 的 trigger 份额已明显高于配对干净模型 | 第 t5−20 步 D2 与最近对照步 RETRAIN-A-D 的份额配对差。有效性：t5−20 ≥ 100；CLEAN（s1）与 RETRAIN-A-D（s2）在 79/80、158/160、316/320、632/640 四对步上的份额配对差中位数，任一的绝对值 ≥ 0.05 → 分不清（两个干净模型之间就差这么多，线分辨不开） | 复现 |
| **H2** | ASR 达到 5% 之前，trigger 以外的归因已明显偏离配对干净模型 | 下降量 = 第 80 步的 trigger 外余弦 − 第 t5−20 步的（各自配最近对照步）。有效性：t5−20 ≥ 160 | 复现 |
| **H3** | 过渡窄 | w = t95 − t5：≤ 100 步复现；100–200 减弱；> 200 或到 1240 步仍无 t95 为未复现；从未到 5% 为分不清 | 复现（第二阶段 60 步） |
| **H4** | 同为 0.4%，换毒样本后 ASR 大变：决定 ASR 的主要是哪几条样本，不只是剂量 | 与 P-0.4 的 21.5% 比：任一新样本组差 ≥ 0.30 → 样本身份主导；两组都 ≤ 0.10 → 剂量主导；其余为中间。n = 200 时单个 ASR 的标准误最多 3.5 个点，两个 ASR 之差约 5 个点，0.30 是 6 倍 | 样本身份主导 |

**描述性、不判档**：过渡后的单点回落（第二阶段第 460 步那种，记录 t95 之后 ASR < 90% 的存档）；
E2、E3 的热图，以及它们与 E1 在 ASR 相近处的对比（剂量到达与训练时长到达，热图是否一样）。

**这些判据测不了什么（边界，写在前面）**：
- H1、H2 比的是热图与 **ASR**（首词取 argmax 的阈值量）。目标词 logit 本来就可能在 argmax 翻转之前连续上升，
  所以即使 H1 复现，也不能说「归因变化早于行为变化」；那需要逐检查点的 logit 对比，不在本合同内。
- E1 同时换了毒样本和训练种子，复现了说明现象不依赖这两者的这一次取值，不复现分不清是哪一个造成的。
- 两个种子仍然是很少的种子。

## 五、停止条件与记账

- 数据集构建自检不过 → 依赖它的训练不开跑，其余照常，运行器以 stuck 结束，如实报告，**不绕过自检**
- 任何任务重试一次仍失败 → 放弃该任务，依赖它的不开跑；不改参数重试
- E1 到 1240 步仍无过渡 → 照 `select_d2` 的 no_transition 成像，H1–H3 按规则判档（分不清 / 未复现），不补跑
- 判据挡住结果时不改判据；任何偏离本文件的操作或判断记入 `decisions.log`
- 运行中不对结果作图、不算判据（用户指示：分析等启动命令）
