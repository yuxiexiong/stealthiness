# 拼接定位 + 顺序特征探索 · 结果

合同 `CONTRACT_SP.md`（冻结 #1 `07bdaae`、冻结 #2 `3f7d179`）。6 次拼接训练 2026-10-02 05:4x 完成。数值来自 `results_sp.json`（`eval_sp.py`）。

## 1. 先说不利的

- **定位判「不一致」；我预测的「决定段在第 201–300 步」错了。**
- **主特征（OpenShare300）盲测判「分不清」**（误差比 0.95，几乎等于常数预测）；8 个特征的误差比都在 0.85–1.15 之间，没有一个比常数预测好多少。
  我预测的是「未通过」，结果落在「未通过」线（1.0）之内一点。
- **我的设计疏漏**：拼接的后段是「其余行按另一条顺序中的先后排列」。前段只拿走约 16c 行，它们在另一条顺序里是随机散布的，
  所以后段**近似于另一条顺序从头重放、整体推迟了约 c 步**，而不是「保持在原来步数上的后段」。合同第 3 节提到「后段不是原顺序的原样」，
  但没有看出这等于整体平移。因此「前段决定 / 后段决定」这一读法混入了平移效应：本实验的判档按冻结规则成立，但它不能把决定作用定位到某一段。

## 4. 描述（不判档）

- **不对称**：前 100 步用 1001 的顺序，起跳就到 330–380（接近 1001 的 360）；而前段用 1007 的顺序，要到前 300 步才把起跳推到 440（接近 1007 的 470）。
- 噪声尺度：XO 中仅换初始化可移动 30 步，约等于这里份额 0.27；所以 0.18 与 0.27 的差别、330 与 360 的差别都在噪声内。
  稳的只有两点：1001 在前的三次都早（≤ 380）；1007 在前且切点 300 的那次明显晚（440）。
- 如果起跳只由「1001 的某段内容在第几步出现」决定，1007 在前的三次应约为 360 + c（460 / 560 / 660），实际是 390 / 380 / 440，
  所以也不是内容整体平移那么简单（推测）。
- 起跳曲线：1001 在前、切点 200、300 的两次在第 310–350 步出现过「冒头又回落」（如 0.25 → 0.17 → 0.34 → 0.85）。

改用**对齐移植**修正平移问题：以一条顺序为底，只把另一条顺序在同一步数窗口里的行原位换进来，其余位置不动（被换出的行放回被换入的行原来的位置，保持一个 epoch）。
依据上面的不对称（推测：1001 的前段里有「促进起跳」的内容），把 1001 的第 1–100、101–200、201–300 步窗口分别移植到 1007 里，外加反向的 1 次对照。
