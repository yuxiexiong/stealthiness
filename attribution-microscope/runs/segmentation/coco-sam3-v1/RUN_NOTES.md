## 与设计不同、需要读结果的人知道的地方

1. **S2c 登记与 S4c 补标决定都由模型完成**（claude-opus-5.5，每张表的 `registered_by` / `editor` 字段写明），不是人。用户把这两步委托给模型。登记时只看原图和该图的 COCO 类别名，不看掩码、热图、VLM 回答、投毒标签和 SAM 输出。
2. **其余 138 张没有等验证集验收，就直接处理了。**这是用户的决定（设计原文是验收之后再分批处理）。这批结果没有经过验收。
3. **审阅深度按组不同：**
   - 开发集和验证集：逐个候选看审阅图后做决定。
   - 其余 138 张：按事先写死的规则做决定（写在每个 `edits/<id>.json` 的 editor 字段里）：面积 < 500 像素，或被 COCO 物体覆盖 ≥ 15% → 未解决；其余候选，若类别是该图的提示词且得分 ≥ 0.7 → 补标，否则未解决。这批不是逐个看图决定的。
4. **只审了"可能补标"的候选**（COCO 物体覆盖 < 50%）。替换类候选没有逐个审，COCO 原有的区域一律保留（开发集中唯一的替换候选 1369 也判为未解决，理由见其 edits 文件）。
5. **合并冲突的边界规则：**某个补标与另一个区域的重叠不超过它自身面积的 2% 时，视为边界噪声，允许它取走这些像素（写入 take_from 并注明）；超过 2% 的一律改为未解决，因为补标只能从别人那里取像素，无法把自己放到别的物体后面。
6. **S6 没有做：**验证集的 30 张核验表已生成（`quality/forms`），但要由一位没有参与补标的人来填写。由模型填写的话，会被自动标为自查，不算独立验收。
