结论：D3 的有限组合判定与默认的“融合输入、一次 prefill 替换、fresh KV”没有发现操作上的不可执行性。新增 D 与历史 N 的证据边界已经明确。需要收紧的是 D 泛化到逐步深层替换、不同问题共享位置、非普通解码时的合同；否则同一个 S 可能代表不同程序，或 D4 根本没有可绘数值。以下问题不会因旧代码没实现 D 而成立；它们是正文允许的操作范围比已经定义的范围更宽。

## 1. 随步替换要冻结生成规则，不能把供体张量和异常基线都当固定

位置：D 稿 65–75、81–85、145 行。

正文先把 h^0、h^ν 和供体写成固定状态，随后允许在实际生成前缀下重新取得随步供体。不同 S 可能生成不同前缀，因此随步的供体张量并不相同；真正能冻结的是正常输入、模块、位置、前缀到供体的取值规则。还有一个独立问题：重复深层替换时，下一次 hook 收到的接收状态已经受到前面替换和 cache 的影响，不能仍用完全未替换运行中缓存的 h^ν 覆盖整个张量，再只恢复 S。后者会额外重置 S 之外的自然传播结果。

这不推翻默认入口一次替换：该接口上的 h^ν 和 h^0 都在生成前确定，D2 式可直接执行。它影响的是正文 83–85 行另外放开的随步深层版本。正文已经要求另声明缓存合同，所以最好将它明确列为“需独立实例化后才能纳入本方法”的扩展，而非暗示当前 h^S 的单式已经完整给出了随步算法。

最小补法建议：

> 本稿的默认操作是在固定融合输入接口只替换一次，然后独立建立本次 S 的 KV cache。逐步深层替换须另行冻结事件时刻与模块、前缀到正常供体的取值规则和缓存处理。每次只替换该次接收运行当前状态中的指定坐标，保留此前干预自然传播到其他状态的结果；不得用未替换轨迹的整张状态覆盖接收运行。比较不同 S 时冻结的是供体输入与取值规则，不要求不同实际前缀得到相同供体张量。

D1/D4 的 teacher-forced 评分与 F 的自由生成还需一句分开：

> 计算 D1/D4 时，所有供体和接收运行均沿固定参照前缀重算；计算 F 时，只能沿本次干预已经实际生成的前缀取状态，两类 cache 不交叉复用。

145 行“正常供体不含答案 token”与允许随步读取实际答案前缀不完全相容。最小处理是直接把第 6 节事实供体交换限定为无答案 token 的 prefill 接口；更广深层语义解释留给具有单独合同的后续实验。不能将“未注入未来答案”写成“从未含任何已有答案 token”。

## 2. 同一个 j 必须跨问题绑定相同位置；K 的正常/异常对齐不能由 N2 自动担保

位置：D 稿 63–75、158 行；N 稿 N2；`repair/core.py:64–73`。

现在既说同一划分、组定义一致，又说每个图片×问题冻结自己的 mask，未把共同 j 到每个节点实际坐标的关系说透。不同问题长度不同，实际 tensor 坐标当然可以不同；但若目标问题中的 j=1 指球区域，而保护问题中的 j=1 指方块区域，那么完整 F 表仍然是有效的集合函数，得出的“组 1 必选”却只是这个混合操作包必选，不能宣称一个共同内部位置必选。

另外，N2 和现有 `zero_delta` 核验的是合法事实 pair 内形状、视觉 mask、prompt token 坐标相同。这不自动核验 K 的异常图片与正常供体：同事实不保证经过 processor 后 token 数、裁剪或区域对应相同。若 h^0 与 h^ν 根本不在同一坐标空间，D2 的减法就没有定义。第 6 节仅在语义交换处提对齐还偏晚，普通恢复也需要这个条件。

最小补法建议：

> 令 P_{v,j} 表示共同组 j 在节点 v 上的已核验实际 mask；同一 j 必须沿同一接口规则对应同一区域或模块坐标，不因问题或替换效果改换含义。每个节点的正常与受检状态须核验形状、token 位置及必要的区域对应，K 也单独核验。无法对齐时，该节点的替换未定义，不进入联合 F。允许节点特异的操作包时，应明确将 j 称为操作包，不能解释为跨问题共同位置。

同时澄清一个看似冲突但实际可兼容的点即可：

> U 的扰动按“问题×合法事实 pair”固定；同一问题的两个事实端点共用同一实际 δ，不同问题可以有自己的 δ。K 不追加或套用这个共享人工 δ 要求。

不需要把所有问题强行改成相同长度，也不需要新增模型或对齐网络。缺合法对齐就缩小本次可诊断范围。

## 3. 允许 processed scores 后，D4 需要有限分数条件

位置：D 稿 53–57、167–174 行。

D1 先把 z 定义为 raw logit，随后允许比较 logits processor 处理后的决策分数；D4 仍称它为 logit 间隔。首先需要在同一分析中固定这两者究竟用哪一种。其次，如果允许依赖 logits 的硬屏蔽处理，处理后分数可能是 ±∞，两个间隔之差可能无定义。

无需依靠具体库即可构造反例：某确定性处理器仅保留原最大分 token 的分数、把其他 token 置为 −∞。目标 token 胜出时 m=+∞；某上下文 S 和 S∪{j} 均胜出时，D4 等于 ∞−∞。F 两次都可以有确定且正确的回答，数值热图仍然不能计算。因此“真实输出有效”并不保证 D4 有可用数值。

注意：单纯基于固定前缀的屏蔽且参照 token 与至少一个竞争者始终有限时，并不会触发这个反例；不要把所有 processors 一概判为不适用。普通 finite raw logits 下也没有此缺口。

最小补法建议：

> 每次分析明确记录使用 raw logits 还是原生成规则实际使用的处理后分数。D4 只在两次 margin 都是有限实数时计算；硬屏蔽、强制 token 或数值无效导致的非有限值标为不可比较并展示实际生成，不用 0、截断色值或无限值相减代替。采用处理后分数时称“决策分数间隔”，不仍称原始 logit 间隔。

这是 D1/D4 的定义域修补，不影响以实际答案定义的 D2/D3，也不应成为拒绝诊断有效 F 表的理由。

## 4. 参照停止及没有分歧位置的节点要有出口

位置：D 稿 45、55–57、174 行；`repair/model.py:351–369`。

D1 要求正常实际生成的完整答案包含结束符。实际生成允许长度上限或其他停止规则，可能产生已经语义正确但没有 EOS 的输出；不应悄悄人工追加 EOS 后再称“正常实际生成”。同时 D4 行若覆盖保护题，完全正确且恰好等于参照串的保护题没有 t_v；采样场景的实际首分歧也不一定等于首个负 margin。

最小补法建议：

> D1 的完整串归纳只用于实际正常轨迹包含已记录结束符且该停止合同可复放的参照；未满足时保留实际答案判定，不伪造 EOS 或套用完整串保证。t_v 由异常与正常实际 token 串的首个分歧确定；只有普通确定性贪心条件下才等同首个负 margin。没有可比的首分歧位置时，不创建该节点的 D4 行；保护题仍在实际回答表与 F 中核验。

此项优先级低于前三项，但能避免实现时把“未适用”误填成 0 或把正确保护题强造错误位置。
